# 扩展记忆检索实验协议 v2.0

本轮用户要求推送部署、重写报告、扩充场景，并明确禁止造假。协议先于正式运行冻结；产品代码固定为 3db2038，不依据本轮结果调参。测试夹具与评分器的错误可以修复，但必须保留失败运行并标注原因。无论文式人群推断，不宣称盲测或独立真实用户保留集。

## 范围和可见内容

检索函数仅看查询、scope、可选 subject key 和隔离库；gold 只在驱动侧。目标是取出回答所需的**原始证据内容**，不是生成回答。计分以实际展示的完整已知原文片段为依据，等价 Fact/Module/Claim/关系端点均可；ID、隐藏 provenance 或截断的片段不算取到。片段检查不是通用语义评分，不测改写回答正确性。另审计完整 packet 的禁止内容，包含 concept graph、heads、paths、guidance 与 provenance，防止仅检查 items 漏报。

## 分组

保留 v1.1 六组：full、facts_only、no_relations、no_kernel_routing、no_head_cache、recent_facts。no_relations 仅关闭 MemoryEdge 路径，不关闭独立概念附件；事实组仍保留核标签、scope 与 fact edges。旧版只运行 full 作同数据对照，不把前后差异当作每个优化项的单因素因果贡献。

预算固定为 1,800 / 2,800 / 5,600（字符 token 估算）；固定 2 次重复用于稳定性与计时，不增加统计样本数。校准 seed 101/102；正式 seed 2001–2006。每两条轨迹各追加 256 / 1,024 / 4,096 条同项目历史干扰；体量分层单列，不当作真实用户分布。

## 场景

保留原 14 类，但明确标为已知回归家族。新增家族：

1. 不提供主题 ID 的精确词项召回。
2. 英文大小写变化。
3. 别名/同义口语查询（不提供主题 ID）。
4. 输入拼写错误。
5. 一个查询同时要求两个主题。
6. 多会话的独立与受助尝试。
7. 同主题多次目标纠正，当前与历史分开计分。
8. 同版本摘要与原子事实的具体限定条件。
9. 重要片段位于超过 900 字正文的尾部。
10. 明确一跳依赖与返回位置。
11. 两跳依赖需求（如系统一跳上限导致失败，照实报告）。
12. 密集高价值边中一个旧但必要依赖。
13. 长历史中的罕见精确词项。
14. 同主题、同词项的大量近期干扰与旧事实。
15. 跨 checkpoint 隔离。
16. 归档事实及其派生摘要排除。
17. 过期事实及关联路径排除。
18. 概念附件的答案字段和私密人因排除。
19. 零匹配未覆盖主题。
20. 泛化词项造成的未覆盖问题误召回。
21. Human 同会话、换会话与到期控制（换会话为新增，其余保留原家族）。

各家族查询数由 fixture 清单核对，报告以实际生成数量为准，不预填成功率。原子 fixture 直接建表，不冒充真实事件链或真实摘要合成。

## 状态链路单独验收

调用仓库既有真实 API/Event/reducer/worker 测试，覆盖幂等、即时指导、跨会话、辅助证据、自述不能升级掌握、合成与撤回、旧纠正不能覆盖新偏好。JUnit 保留每项结果。它是工程合同回归，不能并入检索准确率，不代表完整 Tutor/LLM 或真实学生试验。

## 评分与审计

分别报告：必要原文证据覆盖、全证据齐备率、gold 精确率、负例空返回、Human 指令、完整 packet 禁止内容、证据等级/过期/历史状态、预算、稳定性和 median/p95。

每个条件保存完整 packet 和逐条判定。禁止内容使用仅存在于隔离夹具的完整唯一哨兵片段，不参与查询或匹配排序。对合法历史旧版本，仅在明确历史路径出现时放行。禁止节点 scope 由 fixture 独立记录，评分器不复用生产 scope 判断。

每次运行记录代码、fixture、协议、驱动 hash、依赖版本、命令、时间、输出；新旧必须使用相同 fixture/gold。正式运行后不改测试以提高分数。异常区分产品失败、评分/夹具错误、环境错误；环境失败不记成产品零分。所有失败样例进入报告附录。

## 限制

仍是程序合成数据，无自然用户采样、在线 LLM、语义改写评分或真实学习收益。中英文/别名/错拼/二跳是压力案例，可能超出当前算法支持范围；不能删掉这些失败来宣传 100%。服务器验收只用只读健康/版本/权限检查和无线上卷的隔离容器测试，禁止以真实用户写入制造实验数据。
