# LearnFlow 离线记忆组件消融协议 v1.1

实验目的：在同一合成证据库、查询、时间与上下文预算下，测量各记忆读取组件对证据覆盖与开销的贡献。协议在正式测试运行前冻结。工程检索结果不代表 Tutor 回答质量、学习收益或全部五核架构的因果价值。

## 被测系统与边界

只读调用当前 `learnflow_core.five_kernel_context.build_five_kernel_context`。不复制排序算法、不启动应用、不访问日常数据库、不运行模型、不使用网络。实验在独立输出目录实现，各条件使用同一临时 SQLite 基库的独立复制，结束清理数据库。允许在实验库创建/重建 KernelHead；不修改仓库源码。

夹具直接构造 Event/Mutation/Fact/Module/Claim/Edge 与状态投影，覆盖 Structure、Knowledge、Human、Value、Practice。它测的是读取已有记忆的行为，不验证 reducer、信息抽取、模块合成器质量或真实用户纠正流程。模块是人工构造的、由对应事实支持的无损内容压缩。gold 单元和可接受的事实/摘要表示存在评测侧文件，不送给被测函数。

## 条件（固定）

| ID | 干预 | 保持不变 |
| --- | --- | --- |
| full | 正式函数与相应 ContextPolicy | 参照条件 |
| no_kernel_routing | deep_kernels 改为全部五核，取消按任务的分核深读限制 | 核标签、身份/隐私、排序、摘要、关系、预算均保留；并非删掉整个五核数据模型 |
| facts_only | 实验库移除 Module/Claim 及相连派生边，保留全部原子事实，重建热投影 | 原始内容、证据等级、其余 Fact 关系、策略和预算 |
| no_relations | policy.max_paths=0，关闭 MemoryEdge 一跳输出 | 节点检索和其他投影保留；本夹具不含 ConceptAnchor，所以不声称消融全部概念图能力 |
| no_head_cache | 每次从 KernelState/MemoryNode 重建所有头部，再调用原函数 | 头部的内容和策略保留，只取消缓存复用；主要检验性能与内容等价性 |
| recent_facts | 每学习者/项目仅保留最近 24 条有效原子事实，移除其余记忆节点并重建头部 | 当前短期人因控制状态仍保留；此项是近期事实基线，不是仅对话模型 |

不得为使完整系统胜出调整查询、gold 或干预。无差异和倒退均报告。干预发生在实验库或实验进程内的临时函数替换，不新增生产 capability、事件或状态权威。

## 数据与测量

- 校准集使用 seed 101/102；正式集使用 1001–1012，不依据正式结果调整参数。
- 每条合成轨迹包含不同主题、时间间隔、同项目/跨项目干扰，固定 14 个查询模板：旧锚点、目标纠正、多事实压缩、依赖邻居、Practice 分核、Learning Design 分核、辅助与独立证据、跨项目隔离、当前人因、过期人因、撤回事实、未覆盖主题、近期事实控制、近期与旧事实混合控制。
- query 用中文自然表述与真实课程术语；subject key 由夹具模拟上游已经解析的主题。结果不衡量端到端主题解析或自然语言语义泛化。
- 预算固定为 2,800 与 5,600 估算 tokens；条目/路径上限沿原 policy。前者为常用项目预算，后者为预算敏感性分析，不称为当前所有模式默认值。
- 每个查询/条件/预算重复 3 次，固定检索时钟；随机化条件顺序。重复调用用于时延与确定性检查，不作为新的独立样本。
- 质量主指标：需要证据的查询中，必要信息单元覆盖率；任一事实、摘要或关系端点真正展示相应内容都可得分，仅有 ID 或 provenance 引用不得分。
- 次指标：展示单元精确率、全覆盖查询比例、当前/过期人因指令正确性、未覆盖主题返回空的比例、scope/失效/答案与 Human 原文泄漏、证据等级保真、预算与稳定性。
- 失效旧版本作为明确标记的历史关系端点时单独记录，不能计作“当前事实错误引用”。不以检索无关项冒充回答幻觉。
- 成本指标：每次检索墙钟耗时、估算上下文 tokens；不包含建库，也不包含 LLM 调用或合成成本。报告原始样本、median/p95；p95 仅描述本机合成负载。
- 对每条轨迹先平均，再计算相对 full 的配对差值和轨迹级 bootstrap 区间。只有 12 条程序生成轨迹，区间只描述这个合成分布，不作人群显著性推断。

## 校准与审计

验证评分器接受等价 Fact/Claim 表示、拒绝仅 ID 引用和截断内容、识别旧版本及跨作用域内容，并区分合法历史端点。验证六组确实运行、预算记录来自实际 Packet、网络被阻断、配置数据库哨兵不被打开/修改。

先在校准集修复脚本、评分器或环境错误，再冻结脚本/协议/夹具 hash 并执行正式集。正式结果出现生产检索失败时保留，不修改产品实现来提升成绩。输出逐查询 JSONL、CSV、输入/gold、元数据、汇总、图表与结果报告。

## 校准阶段修订记录

v1 的两个校准轨迹显示所有有 gold 的查询均需要近期窗口外的事实。这只能衡量长历史压力，缺少近期任务控制。正式运行前修订为 v1.1，增加一项近期事实任务和一项新旧混合任务，其余样例、gold、预算和生产排序不变。保留 `pilot-v1` 原始结果；它不并入正式数据。这个修订用于暴露近期基线的适用场景，不用于提高完整系统成绩。
