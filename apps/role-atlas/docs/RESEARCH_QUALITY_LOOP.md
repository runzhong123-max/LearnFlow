# 岗位研究与迭代质量闭环

本页细化已有冷启动与迭代 Skill 的执行行为，不新增 Agent、学习状态权威或发布协议。

## 冷启动

用户确认的 `roleDescription` 是岗位边界，任务归并、知识技能、能力和工作过程生成均读取它。用户资料继续作为证据；开启联网时，现有资料不会取消独立检索与交叉核验。

初轮派生后确定性检查每项任务：

- 知识点和技能点各有明确类型、适用边界、评价条件、真实来源及合法 `requires_skill` 关系。混合领域、泛化能力和孤立节点不代替完整支撑。
- 任务具有 `requires_capability → capability → contains → capability_unit` 链，能力单元具有可观察行为和完整培养规格。只有一个已证实任务时可形成候选能力，不声称已验证跨任务迁移。
- 任务桥接到存在的工作场景，场景有触发、结果、至少两个通过流程边相连的行动/判断及交付物；仅存在桥接不代表过程已闭合。

可研究的缺口回到派生流程，默认至多额外两轮。后续轮只重做仍有缺口的知识或过程任务组；实践、教育等不同检索角度可补充初轮技术文档。补研正文同时供给知识、能力与工作过程分支。定点查询累计最多 12 条；单组知识生成保留原有的引用核对与一次局部修正。若外部检索不可用，合法已存原文仍可驱动模型补齐。

合并保留已成功的节点、关系和过程，不按到达顺序截断既有成果。已有能力同名不同临时 ID 按同一身份检查覆盖，避免重复误判旧能力缺单元。中间语义版本通知仍只发一次，最终 `build.run.completed` 只在修复循环结束后发一次。有剩余覆盖缺口的产物保留候选与具体诊断，不通过发布校验。

## 迭代

`maxRounds` 默认 4，可显式设置 1—6；研究计划累计最多 48 条外部查询。深研与风险修复都按具体任务缺口排工作项；下一轮优先未尝试的工作项，并按尝试次数更换来源角度。提供资料不会将工作项改成无需研究；关闭联网只禁止外部查询，合法原文内的模型研究继续生效。时效模式在无新来源时仅做可验证的日期与来源检查，不以重新标记日期创造版本。

风险修复必须实际减少所选缺陷、改善任务覆盖/证据，或完成明确挂载反馈所需的定义与映射改进。文字定向目标按知识技能、能力、过程、证据或时效维度关联实际发现，不能出现“仅有用户工作项而没有修复目标”的空计划。节点定向范围继续由既有范围验收器约束。

评估发现的后续缺口会进入下一轮。真实进展继续研究；连续两轮无进展且已尝试所选工作项后停止，也受总轮次与查询预算约束。拒绝的候选不得作为后续基础；下一轮从已验收最佳候选或原始快照继续，已取得的合法研究资料另行保留。检查点新增字段均有默认值，兼容旧阶段检查点。引擎默认 `recursionLimit: 80` 容纳明确的研究预算。

自动深研与风险修复继承父任务的 `webResearch`，旧调用方省略时默认开启。调用方须同时传入实际搜索配置。默认自动风险修复不再隐式关闭联网或跳过资料内模型补齐。

## 挂载反馈

可选 `learningMountFeedback` 为 `{ roleNodeId, reason, researchGoal }[]`。反馈形成真实研究工作项与定点模型上下文；定向请求只接受选中节点及合法下游知识点的反馈。沿已有知识/能力关系反查所属任务，为该点补定义与来源；不改写用户原始提示词。

不可变合并默认保留已有事实。仅允许有可核对原文的显式反馈目标修正 `learningDefinition`，或补齐缺失的能力单元培养契约；旧 ID、类型、摘要与既有来源保留。新增证据绑定明确指向教学规格字段，标记推断，不能成为学习者已掌握的证据。反馈仅被显示、改名或添加无关来源均不满足风险修复验收。真实学习路径挂载仍由其现有模块执行与校验。

## 验证

`tests/research-quality-feedback.test.ts` 使用合成资料与假供应商，执行真实 LangGraph：覆盖质量反馈后新资料进入三条生成分支、单任务能力补齐、严格知识/技能与过程覆盖、文字定向离线研究、四轮逐步关闭不同缺口、查询公平排队，以及挂载反馈定义修正穿过不可变合并。现有回归继续验证用户范围、证据引用、无变化结果、来源历史和旧快照保留。测试不读取生产项目或用户附件。

Contract impact：已有 Role Atlas 请求新增向后兼容可选反馈字段与研究预算范围；不修改三类主 Agent、五核或 EvidenceEvent 写入链，不改变学习者掌握证据语义。
