# 岗位快照迭代 Skill

状态：`implemented vertical slice`

## 1. 一个 Skill，三种功能类型

产品只暴露一个 `迭代岗位快照` Skill，但每次运行必须明确服务于三种功能之一：`时效迭代`、`深度研究` 或 `风险修复`。`repair / expand / refresh / verify` 仍是内部工作项；`verify` 是三种功能共同的结束阶段，工作区实例化不再作为岗位包迭代类型。

- 时效迭代：更新标准、技术环境、市场要求和带日期的事实，不轻易改动稳定任务骨架。
- 深度研究：处理边界不清、证据薄弱、能力抽象不当、事理或学习路径缺口。
- 风险修复：以最小补丁处理重复、非法关系、孤立、失证、错误映射和跨空间矛盾。

未显式选择时可由目标和检查发现自动判断，但最终契约仍记录实际功能类型。

Skill 支持三种发起方式：

1. `autonomous`：自动检查全局快照，选择预期价值最高的工作组合并研究。
2. `co_guided`：默认。用户目标增强自动发现，处理目标邻域和核心可用性问题。
3. `user_directed`：只围绕用户提示和选中节点研究，但协议不变量错误始终进入工作组合。

## 2. 工作流

```text
固定当前不可变快照
  → 建立迭代契约（目标、范围、证据政策、预算、停止条件）
  → 结构检查与机会发现
  → 形成有界工作组合
  → 按工作项定向 Search + Extract
  → 必要时重建语义图、事理森林、证据层和快照章节
  → 约束聚类与确定性安全修复
  → 再检查、Agent 探针、信息增量与核心回归评估
  → 最多一次有条件补充研究
  → 新不可变静态快照 / 保持当前快照并保留发现
```

运行由 LangGraph 编排，但图内状态不使用进程内 `MemorySaver` 冒充恢复能力。D1 的 `snapshot_iteration_runs` 与 `snapshot_iteration_events` 保存运行输入、阶段检查点、事件和最终结果。有效的新快照进入通用 `snapshot_versions`，项目型运行还会镜像到项目版本树并更新发起会话的固定版本。

### 风险修复与自动发现（2026-09-08）

- 风险修复包含已诊断的任务知识技能缺口、错误映射、孤立节点和过程缺口。这些修复可以需要研究证据，不因其 `research` 分类而被误排除；普通边界扩展仍归深度研究。
- 自动发现保留用户同时填写的重点。知识技能缺口优先按任务独立分派，检索包含任务摘要中的技术、操作及验收上下文；不能用聚合告警消耗重复预算。用户观察、组织实例和开发者干预继续保留为缺口。
- 模型派生读取本轮明确发现及目标。缺少新搜索结果时，开启研究的任务可复用已有合格原文；关闭联网且没有附件仍只执行确定性检查与补丁。补齐任务知识时使用固定任务 ID，可追加本轮新资料，已有节点、关系、证据与引用继续保留。
- 检索结束不等于修复完成。工作项在候选检查中确认原问题消失后才完成，其余为 `known_gap`。风险修复的验收需要选中问题或对应覆盖/证据指标的实际改善，单纯多了来源或无关节点不能算成功。
- 第一轮部分改善且仍有可研究工作时，第二轮更换证据类别研究未解决项；最多两轮，不重复相同查询，不对空计划无意义续跑。已验证的第一轮改进跨检查点保存，后续候选失败时可保留它。
- 图结构告警每次重新计算，历史审计投影不能充当缺陷仍存在的证据。发现按代码与稳定对象去重；标签变化不能伪造问题消失。已消失的任务缺口同步清理它所拥有的语义校验消息，其他校验继续生效。

工作台区分执行状态与领域结果：`completed` 任务可显示“未生成新版本”或“已更新 · 仍有缺口”。展开本轮结果能看到已尝试的查询、工作项、实际保存版本的知识技能覆盖、剩余问题及拒绝原因；旧记录按运行 ID 与项目 ID 读取同轮领域结果补齐，不重跑历史任务。历史版本入口固定到该轮版本，不改变当前会话基线。

兼容性：复用既有迭代 Skill、事件种类和 D1 表；增加的检查点字段与 job 结果摘要均为可选字段。无新主 Agent、五核写入或学习掌握证据。回归入口：`tests/iteration-risk-repair.test.ts`、`tests/iteration-outcome.test.ts`。

## 3. 结构检查不是粗糙质量门

检查发生在冷启动和每次迭代之后，覆盖：

- 协议与可遍历性：唯一岗位根、关系端点、非法环、快照时间；
- 同维度语义重合与维度污染；
- 任务—知识技能相对覆盖、任务—事理覆盖；
- segment 级证据解析、直接证据和来源多样性；
- 未来来源、陈旧技术来源与目标时点；
- Agent 精确读取、别名消歧、核心快照章节与证据解析探针。

只有机器可证明的协议不变量错误会阻止新快照写入。节点少、技能稀疏、语义相似、事理不足等问题都保留为 `finding / work item / research topic`，候选图谱仍然展示。知识技能不足按任务覆盖关系判断，而不是设置“必须有 N 个节点”的固定门槛。

检查结果分开描述 `core` 与 `frontier`：已接受核心关注回退和可用性，研究前沿允许带明确认识状态与证据边界的增长。Agent 探针用于发现“JSON 合法但工具不好读”的结构问题。

## 4. 检索与并行策略

检索单位是工作项/发现簇，而不是逐节点盲搜。不同工作意图映射到官方标准、招聘市场、工作实践、技术变化、教学设计、未来信号和用户焦点查询。单轮最多 12 条查询，来源上限 4—20，最多两轮；Tavily 继续使用 Search → 排序去重 → Extract 的来源摄取链。

研究、确定性修复和模型重建彼此隔离：悬空边和确切重复可直接修复；语义近似、组织特例和证据缺口进入研究。未来来源只有在每个受影响对象都有替代证据时才自动删除，避免“修复时间问题却让事实整体失证”。引用迁移器保持未变端点的边 ID，只有端点确实改变时才同步迁移边引用。

## 5. 是否创建新快照

快照始终是一个确切、不可变的制品。`as_of` 表达认识时点；revision 区分同一天的不同认识状态。一次迭代在满足以下条件时创建新快照：

- 协议仍有效；
- 已接受核心没有新增结构/证据错误或 Agent 可用性显著回退；
- 风险状态、健康轴或信息增量至少一项得到可说明的提升。

未达到条件并不丢弃运行。契约、搜索、发现、失败分支和已知缺口仍可恢复，当前快照保持不变。

## 6. 产品与 API

- 通用页面：`/snapshots/:snapshotId/iterate?profile=co_guided`；项目、版本和会话是可选路由提示。
- 启动器：每个有快照的岗位项目和内置岗位都显示同一个 `迭代岗位快照` 圆角卡。
- API：`POST /api/snapshot-iterations` 返回 NDJSON 事件流；`GET /api/snapshot-iterations?snapshotId=...` 恢复最近运行。
- 旧 `/risks` 页面会重定向到统一迭代页面；旧 risk API 暂时作为兼容层保留，不再由产品入口调用。

迭代页面采用“左侧简报 + 右侧 Agent 运行会话”的两阶段结构。左侧只负责确认发起方式、目标、节点、时点、联网与附加资料；开始后，右侧按 Codex 式对话时间线展示：

- 当前“正在思考”的可核验摘要与总耗时；
- 已配对的工具开始/完成事件、单工具耗时、输入与输出；
- 并行搜索、模型重建、结构整理、回归评估和快照写入的明确运行状态；
- 面向用户的最终回答，以及默认折叠的结构体检、语义 Diff、工作项和已知缺口。

逐条结构发现不会直接淹没主时间线，而是聚合进 `snapshot.inspect` 工具卡并在最终结构体检中按需展开。供应商配置在运行前失败时，也会在同一对话中保留用户目标并显示错误，不会退回空白等待页。
