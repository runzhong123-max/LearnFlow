# Role Atlas 个人工作空间与对话工具

Contract: `role-atlas.workspace.v2`。范围仅为 Role Atlas；复用 LearnFlow 登录身份和既有固定版本岗位包协议，不读取或写入 LearnFlow 五核，不新增主 Agent。

## 产品对象与入口

项目保存岗位目标、会话、资料、执行和版本。对话是项目中的独立讨论与执行上下文；新建对话不能创建另一个项目、复制岗位包或重置其他对话。岗位包是项目可复用的成果，公开发布是独立操作。

中间展示台保持同一个组件框架，承载图谱、任务、卡片、证据和空项目状态。冷启动、迭代、节点深化、工作区接入是对话侧栏中的工具，使用既有稳定 ID：

| ID | 目标 | 写入范围 |
| --- | --- | --- |
| `cold-start-role-package` | 建立首个岗位快照 | 当前项目、当前对话的新版本 |
| `snapshot-iteration` | 补研并完善岗位包 | 固定基线上的候选版本 |
| `node-deepening` | 围绕明确选中节点完善 | 固定基线上围绕选中节点研究的候选版本 |
| `workspace-instantiation` | 从用户提供的工作资料提取依据 | 当前项目来源与候选版本 |

各工具保留独立的输入校验、证据和生成算法，共用对话中的操作与进度呈现。展示台的流式预览是未提交结果，不会自动成为正式项目版本。持久化完成后才刷新可引用的不可变成果。

新建项目是全局操作；新建对话在项目助手顶部；版本和发布属于项目标题区域；删除放入项目管理菜单，回收站属于个人空间。删除是可恢复的软删除；已发布的不可变岗位包不被级联删除。恢复项目不重启取消任务。

## 迭代工具的完整选项

对话栏内恢复深度研究、风险修复、时效迭代三种功能，以及目标增强、自动发现、定向研究三种发起方式。普通迭代默认深度研究／目标增强；节点深化默认定向研究并预填选中节点。配置按对话和工具保留；再次从另一个节点启动深化时替换研究节点，保留其余选择。

研究节点支持语义图谱和事理图谱，可从列表添加、采用当前选择、删除或粘贴 ID。它们限定研究关注范围，结构整理和完整性校验仍覆盖全图；自动发现仍检查全岗位。服务端拒绝不属于固定快照的节点。定向研究允许只选节点不写文字；目标和节点都空时不得提交。

目标时点可留空。时效模式留空取提交当日，其他模式沿用基线；显式日期参与来源检查、修复、评估及最终快照／brief／manifest的一致性写入。有未解决的目标时点错误时不得生成该日期版本；仅日期变化不算证据增量。

附加资料、联网开关和 LearnFlow 学习路径都传入同一个迭代请求。学习路径在重建阶段参与对齐，关闭联网且无附加资料时仍只做确定性检查与修复。路径读取失败或用户在准备阶段取消时不提交任务。预算继续使用原有默认值：2 轮、12 个来源、10 个工作项。

任务记录展示实际使用的功能、发起方式、目标、节点、时点、联网状态、资料数量及学习路径标记，刷新后可读；该摘要不返回供应商凭据或资料正文。Contract impact：恢复既有迭代请求字段和运行行为，任务响应仅增加可选配置摘要，不改变五核、主 Agent 或已有快照 ID。

## 对话模式与版本

对话模式为 `explanation`（讲解）和 `iteration`（迭代）。旧记录默认讲解；模式与会话一起持久化。讲解读取固定版本，不暗中触发修改。用户主动选择写入工具时进入明确的迭代操作，执行范围始终可见。

每次执行固定项目、对话、起始版本、快照和独立运行 ID。不同对话可以同时执行，同一对话的写入任务不得互相覆盖。切换对话不等于取消任务；取消是显式操作。

候选提交以数据库事务校验当前项目 HEAD：

1. 基线仍是项目当前版本：结果可以推进项目 HEAD。
2. 另一对话已推进 HEAD：保留当前结果为分支，更新发起对话的结果引用，不覆盖 HEAD。
3. 采用分支结果需要指定预期 HEAD；若再次变化则返回冲突，不静默重试覆盖。
4. 对话、运行、版本必须属于同一项目；软删除或取消会阻止迟到的结果写回。

这里的并行是多个独立任务共享持久化记录与事务提交边界。单机 Miniflare 部署仍是单机宿主；检查点与事件持久化不等于已经部署多节点队列或具备进程故障后的自动调度。不能把浏览器断开后的继续执行等同于无限期任务保证，实际恢复能力以运行状态和检查点为依据。

## 用户隔离与个人岗位包中心

生产身份只能由服务端 LearnFlow 会话桥接取得；客户端的项目 ID、对话 ID、用户名称或维护者名称都不是授权依据。所有私有资源读写、任务状态、版本、发布、导出、来源访问必须验证真实归属。跨用户私有资源统一不可见，按资源不存在处理。

个人列表只列当前主体拥有的项目和有项目发布关联的岗位包，包括尚未发布的项目成果。管理员的维护权限不能让其个人列表默认展示全部人的私有内容。公开市场使用独立的公开发布过滤，不以客户端传入的 `visibility` 参数绕过归属。

历史无主项目保留原数据，不按登录顺序或维护者名字自动分配。普通用户不可见；明确的管理员维护入口才可处理。生产数据认领或迁移必须单独核对来源并授权。

保存岗位包严格使用用户选择的可见范围：私有成果进入个人中心，公开成果才进入图谱市场。编译和发布采用同一个不可变制品；同版本号仅接受项目版本、可见范围、证据策略等全部相同的幂等重试。任何一项变化均返回冲突，不能以先前的公开制品代替当前私有保存请求。

新项目的默认发布身份是 `role-package:project:<projectId>`，同名岗位在不同用户或项目下仍各自独立。已有发布记录的项目复用自己的历史包线；显式包 ID 也必须通过归属检查。不会改写原快照 ID 或迁移历史成果。

动态页面、RSC 与私有 API 响应使用 `private, no-store`，不能在缓存中跨用户复用。公开发现 API 独立按发布状态和不可变 manifest 的可见性过滤。

## 对话执行接口

- `POST /api/projects` 可指定 `conversationMode`；新建项目默认讲解，创建本身不启动模型。
- `POST /api/projects/:id/conversations` 的 `mode` 与 `PATCH /api/projects/:id/conversations/:conversationId` 持久化模式。运行中的对话拒绝修改模式。
- `GET /api/projects/:id/jobs?conversationId=...` 按会话读取任务；`GET /api/projects/:id/jobs/:jobId?after=...` 返回持久化进度；对应 `/cancel` 显式取消。
- `POST /api/projects/:id/versions/:versionId/adopt` 必须指定 `expectedHeadVersionId`，可选 `conversationId` 表示一并切换该对话后续工作。失败不会覆盖项目或对话；省略对话时已有对话保持原版本。
- 四个工具复用 `/api/build-runs`、`/api/snapshot-iterations`、`/api/workspace-upgrades`。不再使用的 `/api/risk-runs` 与 `/api/workspaces/ingest` 写入接口在鉴权后返回 410 并指向统一工具入口；历史 GET 继续可用。

## 兼容与验收

模式字段采用增量迁移，旧对话默认讲解；原工具 ID、快照 ID、已有发布包身份和来源证据保持不变。旧独立工作台链接保留读取兼容，新日常入口使用统一展示台。此前可匿名读取的私有管理接口现在要求身份，这是有意收紧的访问契约，客户端需处理 401/404/409/410/503。

验证入口：

```bash
cd apps/role-atlas
npm test
npm run typecheck
npm run build
node scripts/verify-personal-workspace.mjs
# 留下隔离测试服务供浏览器验收：
node scripts/verify-personal-workspace.mjs --keep-open
```

HTTP 验收使用独立临时 D1、三名虚构用户和本地身份桩，不使用日常数据库、真实账号或模型密钥。浏览器验收应覆盖：空项目、两种模式、新建与切换对话、工具打开后展示台不消失、任务进度、并发候选分支、个人中心、删除与恢复、未登录提示。实际通过/失败/未执行结果记录在任务最终报告中。

## 单机部署交接兼容

线上 cohost 的 LearnFlow 交接代理同样遵守个人目录边界：从 Role Atlas 交接时转发已验证的登录凭据读取个人 `/api/registry`；从 Graph Hub 交接时只读取 `/api/registry?scope=public`。不回退到全局目录，目录中不可见的发布版本返回 404。部署本版本时应同步更新 `role-atlas-launch-proxy` 的脚本挂载；仅替换 Role Atlas 镜像不足以完成交接兼容。
