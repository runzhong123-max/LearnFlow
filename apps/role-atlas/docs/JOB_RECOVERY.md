# 岗位任务后台执行与恢复

Contract impact: role-job-delivery/v1，registry 2026-09-08.2。既有 Role Atlas 产品执行器修复，不新增 Agent 主接口、LearnFlow capability、学习事件或五核写入。原生产授权仍由用户提交工具任务提供；后台恢复不发布图谱、不提交学习路径挂载。

## 执行与展示

工作台向既有冷启动、迭代、节点深化、工作区接入 API 发送 `Prefer: respond-async`。通过原身份、项目、对话基线与配置校验后，事务保存 queued role_job 和加密执行信封，返回 202。未发送该首部的旧客户端保留 NDJSON 行为。

页面上“正在研究 / 后台增量中 / 自动挂载中 / 已完成”等文案不再由各处自行拼合：`lib/jobs/run-status.ts` 的 `projectRunStatus()` 是唯一投影入口，输入研究进度事件、任务状态与自动挂载记录，输出有序阶段列表（搜集扩大资料 → 确定岗位边界 → 梳理任务与能力 → 展开工作过程 → 深度研究与完善 → 匹配学习课程）和唯一标题文案。研究结束后挂载记录决定末段阶段状态；运行失败或被取消时保留自己的受阻标题，健康的挂载记录不得覆盖未解决的失败。

`role-atlas-job-worker` 是独立 Node 消费者，每 5 秒扫描队列，并行上限 2。消费者用签名内部请求调用原执行器并持续读取连接，不依赖浏览器。内核完成后的冷启动增量也由消费者接续。页面每 6 秒读取任务和已保存事件游标，刷新或断线不会取消任务。沉默模型调用期间 NDJSON 每 10 秒发送空行保活。

执行租约 45 秒、每 15 秒续期；投递领取窗口 120 秒。消费者重启、执行连接丢失且运行租约过期后，原任务最多投递 3 次；不对正常领域失败无限重试。单次执行最多一小时，达到上限保留已有检查点并停止。明确取消、项目删除、对话切成讲解态、版本基线变更均阻止恢复。

已过期的旧任务不会因上线而批量重跑。所有者可点击“从保存处继续”，沿用原 runId、输入、版本与检查点。历史记录未保存的供应商凭据由当前服务器配置提供。若基线已改变，提示在新对话继续，保留现有版本。

迭代阶段检查点保存 candidate、来源、计划、迁移、评估与已完成阶段，恢复从下一阶段开始；事件编号接续已有日志，失败事件不占用永久最大序号。冷启动未完成的计算阶段可重做，已保存产物保持不可变。增量阶段已改变对话基线时停止旧任务恢复，避免重复覆写。迭代版本已写入但 job 未完成时按 source_run_id 对账，避免再次生成版本。

迭代检查点还可保存已验证候选与发现历史，用于有界第二轮失败后的回退。`role_jobs.result_json.outcome` 是有界结果摘要，执行 `completed` 与领域 `no_change` 分开。旧任务没有摘要时，只从相同 jobId、projectId 的 `snapshot_iteration_runs` 回读；不暴露候选全文、附件正文或模型响应，不改变历史任务数据。未采用候选的覆盖指标使用原快照检查结果。

## 身份与凭据

内部 API 只接受专用域 HMAC 签名（绑定方法、路径和 60 秒时间窗）；没有浏览器可传入的身份绕过首部。消费者请求只含任务 ID；服务端从已验证提交身份恢复 actor，并再次执行原 ownership、对话、版本与运行作用域校验。固定四个执行端点，不支持任意 URL。`ROLE_ATLAS_GATEWAY_SECRET` 至少 32 字符；签名和 AES-GCM 使用不同派生域。信封以 jobId 为附加认证数据，不存会话 cookie。

供应商会话级覆盖配置仅在加密信封中暂存，不进入 role_jobs.input_json 或公开导出。成功/取消后清除信封，失败保留最多 24 小时供显式恢复。删除项目、主体不再匹配时不执行；管理员测试收集仍是操作审计，不是学习证据。

## 部署与验证

使用 `deploy/cohost/compose.yaml` 启动 `role-atlas` 与新增 `role-atlas-job-worker`。消费者挂载 `scripts/job-worker.mjs`，复用已有网关密钥，仅访问内部 role-atlas:3000。旧版应用回滚时停止消费者即可，新增表可保留；不改原快照、事件或版本内容。

验收覆盖：签名防伪及重放时间窗、信封篡改与作用域、租约抢占、并行对话、取消与基线变化、断线后保存、阶段恢复完整性、事件连续性、提交后断开浏览器、消费者重启、最终版本唯一性。
