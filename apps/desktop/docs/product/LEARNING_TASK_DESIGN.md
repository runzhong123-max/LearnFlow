# vNext 对话内学习任务设计

## 产品契约

学习任务不是课程目录或掌握记录，而是来自 Conversation 或未来项目关卡的可恢复原子目标。
任务生命周期由正式 LearningTask API 维护并进入全局队列；浏览器本地事件只重建 Skill 的对话
步骤和离线现场。任务不拥有统一的教学阶段，当前
Learning Skill 才拥有具体步骤、分支、循环和支架规则。Tutor 每轮只读 Skill 步骤投影，不能
直接推进步骤、评分或宣布掌握。

```text
明确的“带我学/带我弄懂/带我练”
  -> 在当前对话创建任务
  -> 同步到正式学习任务队列
  -> 选择一个 Learning Skill
  -> 按该 Skill 的状态机教学（可以停留、循环或切换 Skill）
  -> 完成流程（不等于掌握）
```

普通“什么是 X”仍只进入一轮简单讲解。学生也可以先选择“带领学习”，再发送原子目标。
任务进行中仍使用原聊天输入；输入栏上方只显示目标、当前 Skill 步骤、微型进度和一个下一动作。
Skill 切换、完整步骤、循环和支架收进选项菜单；全局任务页只管理开始、暂停、恢复、取消与回到
原对话，不建立竞争性的教学输入区。

## 四个首批 Skill

| Skill | 自己拥有的流程 | 循环与关键边界 |
|---|---|---|
| 清晰讲解 | 最小模型 → 最小例子 → 学生解释 → 换情境检查 | 不懂时换表征或缩小解释范围，不能用空泛追问代替起点 |
| 苏格拉底追问 | 可回答起点 → 假设 → 理由 → 边界检验 → 收束 | 不会时补事实、二选一或句架并留在本步；每轮只追一个连接 |
| 费曼复述 | 必要起点 → 初次复述 → 定位跳步 → 修订复述 → 例子/边界 | 围绕同一个跳步反复缩小和修订；复述不是掌握证据 |
| 示例渐隐 | 完整示范 → 补末步 → 补中间步 → 独立变式 → 策略反思 | 支架后留在原步；独立变式可以换题循环，有提示完成不算独立 |

四个 Skill 只共用同一个轻量任务壳和事件队列，不共用教学阶段。切换 Skill 会从新 Skill 的
第一步开始；它不会宣称旧 Skill 已完成。检索练习、支架和反馈是 Skill 内可组合动作，不强制
做成新的 Skill。

## 事件队列

Skill 事件只追加、带 Conversation 内递增序号，记录步骤进入、循环、学生回应、支架请求和
Skill 切换。任务创建、开始、暂停、恢复、取消、重开和流程完成同步到正式任务事件链；页面刷新后
同时恢复本地对话投影和正式任务队列。

- Skill 步骤与循环是浏览器本地运行事件；正式任务生命周期进入后端 `EvidenceEvent` 账本。
- 两类事件都保持零 Kernel target，不能直接生成 Fact 或掌握状态。
- 普通回复不自动切换步骤；只有学生点击当前 Skill 的下一动作才追加 `skill_step_entered`。该
  事件不表示上一动作通过，更不是正式 LearningTask 的 `phase_completed`。
- “不会 / 不知道 / 要提示 / 跳过”同时追加支架和 `skill_looped` 事件，继续留在当前步骤；
  学生也可以显式选择“再来一轮”。
- 要求复述、判断、补步骤或完成变式的 Skill 步骤，在当前步骤收到一次学习者回应前不能推进；
  支架循环会重新关闭推进条件。这只是交互准入，不评价回答正确性。
- v0.5 已保存的 `phase_entered` 仍可读取，并确定性映射到当前 Skill 的近似步骤；新任务不再写它。
- “完成流程”只表示本轮任务收束；正式能力证据未来仍必须来自独立判题的 `LearningAttempt`。

## 研究与产品依据

本设计没有把某篇论文直接翻译成固定剧本，而是取其可执行且边界清楚的共同结论：

1. Roediger 与 Karpicke 的提取练习研究显示，相比重复阅读，主动提取更有利于延迟保持。因此
   `practice / verify` 要求学生生成答案，而不是继续播放讲义。
   [原始论文](https://learninglab.psych.purdue.edu/downloads/2006/2006_Roediger_Karpicke_PsychSci.pdf)
2. Chi 等人的自我解释研究发现，能把步骤与原理联系起来的自我解释与更好的问题解决理解相关。
   因此费曼复述和样例学习都要求学生解释一个关键关系。
   [原始论文](https://doi.org/10.1207/s15516709cog1302_1)
3. Atkinson、Renkl 与 Merrill 的工作样例渐隐研究支持从完整样例平滑过渡到问题求解，而不是让
   新手立即从空白求解。因此程序性目标默认推荐“示例渐隐”。
   [论文页面](https://link.springer.com/article/10.1023/B:TRUC.0000021815.74806.f6)
4. ICAP 框架把可观察活动区分为被动、主动、建构和互动，强调仅呈现信息不足以保证认知参与。
   因此每个阶段都要求一个学生可见的小动作，同时不把界面点击误当成能力证据。
   [原始论文](https://doi.org/10.1080/00461520.2014.965823)
5. Cognitive Tutor 研究和 ASSISTments 实践都强调问题求解中的及时反馈与按需支架，但提示与独立
   完成必须区分。因此事件队列单独记录支架请求，验证提示词也禁止把有提示成功说成独立完成。
   [CMU 研究](http://pact.cs.cmu.edu/corbett/Corbett&AndersonCHI2001.pdf) ·
   [ASSISTments 官方研究](https://www.assistments.org/evidence-of-impact)
6. Khanmigo 与 ChatGPT Study Mode 的官方设计都把引导问题、分步支架、知识检查放回持续对话，
   并允许用户切换学习方式。因此 vNext 把任务控制压在输入栏上方，而不跳转到课程页。
   [Khan Academy 设计说明](https://blog.khanacademy.org/how-we-built-ai-tutoring-tools/) ·
   [OpenAI Study Mode](https://openai.com/index/chatgpt-study-mode/)
7. ALEKS 的持续“准备度识别—个性路径—周期检查”说明任务规划应考虑先备状态和后续检查；当前
   vNext 只实现最小本地版本，不复制其掌握模型。
   [ALEKS 官方说明](https://www.mheducation.com/highered/aleks/learning.html)

## 当前非目标

- 不在浏览器中判题或产生正式掌握证据。
- 不给所有学习方法强套同一组阶段，也不把 Skill 步骤升级成项目关卡。
- 不在任务创建时生成课程文件夹、讲义或题库。
- 不让模型通过回复文本改变阶段、Skill 或事件队列。
- 不把本地 Skill 事件队列冒充五核、LearningTask 后端权威或长期学习者画像。
