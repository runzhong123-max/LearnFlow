# 五核记忆升级评测与学生试点协议

状态：工程检索评测可执行；真实学生试点尚未执行，尚无学习收益结论。本文不构成学生招募或邀请。

## 1. 工程评测交付

运行后端 `scripts/evaluate_memory_upgrade.py --repetitions 3 --output /tmp/memory-report.json`。
脚本强制创建并清理临时 SQLite 数据库，不接受数据库输入，不执行应用启动或生产 seeded 初始化。
环境里的 DATABASE_URL 不用作测试数据库；运行结束恢复环境变量。报告只包含合成标识与测量值。

报告明确标记 `retrieval_only_not_learning_gain`。363 条合成事实覆盖旧学习锚点、40 条同项目干扰、
320 条跨项目干扰、目标旧版本与新纠正，以及从未出现的主题。事实、事件、归约记录是预制的隔离
投影夹具：本脚本不评估语言提取、真实纠正事件或 reducer 的正确性；这些由专项回归测试验证。

三个比较条件均真实运行：

| 条件 | 实现 | 限制 |
| --- | --- | --- |
| 近期窗口 | 先过滤学习者、项目与有效状态，取最近 max_items 条，再匹配查询 | 旧锚点可能不在窗口 |
| 精简事实 | 同范围有效事实按主题保留最新条，再匹配查询 | 无图关系和教学上下文 |
| 当前五核 | 调用正式 build_five_kernel_context 的 project_tutor 策略 | 包含实际生产排序与上下文开销 |

三者采用同一学习者、项目、有效状态标准，以及当前策略的条数与估算 token 上限。前两组使用精确
合成标记匹配，五核采用现有正式检索；这一差异公开保留，不能把结果当成自然语言语义检索排名。
基线只有事实内容，五核还包含上下文元数据，所以报告分别披露 token 开销，不能将时延差异归结为
单个算法因素。每次调用包含自身查询耗时；数据库建立时间不计入查询时延。样本很少时只报告原始
时延、median 和 max，不宣称稳定的线上 p95。

每个样例独立输出 gold 命中、遗漏、已失效旧记忆引用、无关返回、未覆盖是否返回空、预算和时延。
“不相关候选被检索”不等于模型最终答错；没有生成答案，因此不报告回答准确率或幻觉率。
五核在未覆盖主题仍可能返回项目相关背景，报告不把这种结果隐藏或改成空。

新增回归测试验证评分不伪造成功、三组实际执行、配置数据库不被触碰以及预算和失效过滤。
不设置“五核必须胜出”的断言。新增样例应先独立标注 gold，再运行检索，避免依据系统返回结果改标签。

## 2. 学生试点目的

回答三个问题：记忆是否降低重复介绍与恢复学习的成本，是否提高独立完成与延迟回忆表现，是否让学生
更好地解释错误和选择策略。画像条目数、对话长度和满意度不能替代学习结果。

试点分两步：先做小规模可用性试点（建议 12–18 名自愿学生，作为探索性样本），修复流程和测量问题；
再根据基线方差、最小有意义效果和流失率确定正式样本量。探索性样本不用于宣布统计显著的教学优势。

## 3. 实验条件与分配

正式比较沿用“近期对话、精简事实记忆、五核记忆”三组，使用相同模型版本、提示词中与记忆无关的部分、
题库、评分器、工具权限、响应预算和学习时间。明确记录每组记忆存储、压缩、检索和撤回规则；记忆策略
是主要变化因素。所有组必须遵守来源和撤回安全要求，不故意保留错误记忆来制造对照优势。

按学科基础和前测表现分层随机分组；同一学习者的不同组不能共享记忆或实验期间更新的画像。
初次正式试点优先采用组间设计，避免切换条件时已学知识的残留。需要组内设计时，使用等难度且不重叠
的任务，平衡任务与条件顺序，并在分析中显式处理顺序和练习效应。

预先冻结任务难度、前测、独立成功规则、提示等级、迁移题与分析方案。评卷尽可能对记忆条件盲评。
任何策略修复记录版本与日期，不能将版本不同的数据不加区分地合并。

## 4. 观察周期与指标

建议至少覆盖 2–4 周，安排次日恢复与第 7 天、第 14 天的延迟测验；正式时间表应在开始前冻结。

| 目标 | 记录方式 |
| --- | --- |
| 学习效率 | 达到首次独立成功的有效学习分钟数；明确排除离开页面和长时间空闲 |
| 独立成功 | 无提示、无答案暴露条件下通过预注册评分规则；辅助成功单独报告 |
| 延迟回忆 | 第 7/14 天无提示作答率，记录逾期、缺测与再次学习情况 |
| 迁移 | 已校验且不同于原题的变式独立通过率 |
| 连续体验 | 学生重复介绍已提供背景的次数，恢复到首个有效学习动作的时间 |
| 记忆可信度 | 错误认识率、纠正后再次引用率、过时目标采用率及作用域误用 |
| 学生启发 | 依据固定量表盲评错误解释、概念关联与策略选择理由 |
| 运行成本 | 每次有效教学动作的 token、工具轮次、响应延迟与额外提问数量 |

记录退出与缺测，不把未完成者排除后只比较成功学生。先报告分布、置信区间、各基础层表现及负面案例，
再讨论平均改善。真实兴趣、疲劳和任务熟悉度作为已预注册的潜在混杂因素记录，不从表现自动推断人格。

## 5. 数据与学生控制

开始前明确说明试点目的、条件差异、收集内容、保存期限和退出方式，并取得相应同意。
研究数据使用随机参与者 ID；身份映射独立存放、最少授权，不进入评测报告或模型上下文。
默认保存结构化事件、提示等级、测验结果及耗时；若需要原始对话做错误审查，应另行说明用途，并做
去标识和敏感信息清理。不得将学生原始记忆上传到公共基准或公开仓库。

学生可以查看和纠正系统认识、停止使用某项记忆、退出试点；预先约定退出后的数据删除与保留范围。
测试与代他人提问不纳入本人学习画像。禁止为试验静默覆盖学生的真实任务和正式掌握状态。

## 6. 进入与停止门槛

进入学生试点前：关键误记、撤回、隔离、能力标签回归全部通过；完成一次带记录的端到端恢复与纠正
验收；明确实验负责人和数据处理人；完成低成本回退演练。

出现跨学生数据暴露、纠正持续失效或错误掌握升级时暂停相关策略，保留必要审计事件并修复。
普通负面体验按严重度逐条记录。结束后交付真实样本流转、版本、运行成本、学习指标、负面案例及
不确定性；结果不足以支持五核的额外复杂度时，应缩减或调整机制，而不是补充宣传结论。
