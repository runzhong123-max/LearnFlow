# 原子学习 Skill 研究与选型

## 1. 结论

首批只维护四种能够主导一项原子学习任务的方法：清晰讲解、苏格拉底追问、费曼复述和示例
渐隐。它们不是四套封闭课程模板，而是 Tutor 可按目标和互动情况选择的“主教学策略”。

番茄、康奈尔笔记、可视化、类比、代码执行、资料检索和习题生成可以作为计划中的支持工具，
但暂不成为主 Skill。原因是它们分别更像时间管理、记录格式或媒介能力，单独使用不能自然地
承担“学习—练习—独立验证—复习转交”闭环。

## 2. 共同的原子任务契约

无论选择哪种方法，都必须满足：

1. 目标具体到一次连续互动可以推进，且已由学生明确选择或确认。
2. 启动即绑定一个 learner-visible `LearningTask`，保存计划、暂停点和产物引用。
3. 教学阶段有轮次预算，可按回答调整表达，但状态和准入由服务端裁决。
4. 教学后必须有无提示、表面不同的独立验证；有提示成功不得冒充独立成功。
5. 答错进入确定性纠错、原题重做和已校验变式，不由模型自由决定通过。
6. 正式结果进入复习队列；本轮完成不得宣称稳定掌握。

任务计划仍保持 `learn / practice / verify / consolidate` 粗阶段。Skill 负责主导 `learn`，
也可以在 `practice` 中提供有限支架；`verify` 和 `consolidate` 始终交给现有 Practice 与 Review
权威。

## 3. 研究依据如何转成产品规则

### 清晰讲解

自我解释研究显示，学习者主动解释材料中的关系比单纯接触更有利于理解。因此清晰讲解不能
停在 Tutor 输出：在最小模型和例子之后，必须要求学习者用自己的结构重述或预测新例子。
这影响的是教学流程，不把自我解释本身升级为掌握证据。

参考：[Chi 等人关于自我解释的研究](https://asu.elsevierpure.com/en/publications/eliciting-self-explanations-improves-understanding/)。

### 苏格拉底追问

自然教学对话研究强调 Tutor 会围绕学生当前回答逐步追问、给有限提示并纠正，而不是一次
抛出问题清单。因此本 Skill 每轮只问一个问题，并保留“直接解释”的退出通道。若显式选择
苏格拉底的学生正在首次接触主题，Tutor 必须先给足以回答当前问题的最小知识支架和具体情境；
学生说“不会/不知道”、跳过或只确认时，必须停留在原步骤，不能伪装成已经表达直觉。只有
出现可检查尝试后才能检验条件并连接推理；持续缺少先备知识时应建议切换清晰讲解。

参考：[Graesser、Person 与 Magliano 的自然教学对话分析](https://escholarship.org/uc/item/5bn8r6v3)。

### 费曼复述

产品采用的是“自我解释/teach-back”机制，不把“费曼学习法”当成需要照搬的固定仪式。
学生先用自己的话讲，Tutor 每轮只定位一个含糊词、因果跳步或边界，再要求修订。复述适合
已有接触后的查漏，不适合作为完全陌生主题的第一步。

工程实现不再使用单一“简单/困难”旋钮，而是拆成四个可解释维度：讲给哪类受众、需要说到
定义/机制/边界/迁移中的哪一层、允许多少支架、优先用代码/可视化/类比/形式化中的哪种表征。
这避免“难度”同时改动术语、任务复杂度和帮助量。第一次复述只产生一个未验证候选缺口；
后续最多两轮只修这一处。表达形式达到要求后仍只进入独立验证，不由 Tutor 宣称正确或掌握。
若学生明确没有知识起点，先给三点以内的最小解释和一个例子，再邀请一句自己的话复述。

其核心机制同样由上述自我解释研究支持；最终仍必须通过独立检索与作答验证。

### 示例渐隐

Worked-example fading 研究支持从完整示例逐步过渡到独立解题；在计算机教学中，按功能子目标
标注示例还能帮助新手识别可迁移的程序结构。因此 LearnFlow 采用 backward fading：先给
2–4 个子目标标注的完整示例，先隐去最后一步，再逐步撤去更多步骤，最后用无标签新情境
独立验证。

参考：[Renkl 等人的示例渐隐研究](https://www.tandfonline.com/doi/abs/10.1080/00220970209599510)、
[计算机教学中的子目标标注示例研究](https://dl.acm.org/doi/10.1145/2787622.2787733)。

### 独立检索与延迟保持

教学后的测试不是附加装饰。检索练习研究表明，测试可改善延迟保持；因此四种方法都不能用
“看懂了”结束，而要交接独立验证和后续复习。不过 LearnFlow 仍只把服务端正式判题视为
能力证据，研究结论不替代具体题目的评分契约。

参考：[Roediger 与 Karpicke 的检索练习研究](https://journals.sagepub.com/doi/10.1111/j.1467-9280.2006.01693.x)。

## 4. 选择与组合规则

默认策略是保守推荐而非自动激活：

- “是什么、没听懂、先讲清”优先清晰讲解。
- “为什么、证明、不变量、让我自己推”优先苏格拉底。
- “我来复述、查漏、检验我是否懂”优先费曼。
- “带我做一遍、先示范再让我做、配置/代码步骤”优先示例渐隐。

目标模糊时先澄清，不建任务；学生明确选择时尊重选择，但 Tutor 可以说明不匹配风险。计划可
在一个任务里更换主 Skill，例如先清晰讲解建立模型，再用示例渐隐练习；切换只暂停旧
SkillRun 并保留同一 LearningTask，不复制目标或证据。

不采用“视觉型/听觉型学习者”等固定学习风格标签做选择。方法适配依据来自当前任务性质、
近期可检查表现、明确偏好和辅助需求，而不是稳定人格分类。

## 5. 产物与观测

需要长期保留的讲义、示例、练习和评估继续写入 `Lecture / Exercise / ConceptQuestion` 等
受管对象，任务只保存引用。普通三轮互动可以只保留对话；进入正式验证时，同一任务按需
物化 `/learn/:runId` 附件。

工程评测关注路由、预算、幂等、ownership、验证交接和零掌握写入；真实产品实验至少比较：

- 方法推荐接受率与主动切换率；
- 原子任务和独立验证完成率；
- 不同方法下的提示等级、首题表现和纠错完成率；
- 24 小时、7 天的无提示保持与变式迁移；
- 主观负荷、控制感，以及是否觉得 Tutor 追问过多或讲解不足。

只有这些数据支持时才扩展新主 Skill；新增方法必须先登记适用边界、确定性状态、任务契约、
验证方式和冻结评测样例，不能只增加提示词和按钮。
