# DeepTutor 领域知识供给架构研究

> 研究日期：2026-08-29
> 对象：DeepTutor 论文 v1、官方仓库与公开工程问题
> 用途：为 LearnFlow 的领域知识准备、用户协同找资料、对话内动态补充、讲义与练习生成提供设计依据
> 状态：研究结论；不直接改变运行时权威、五核或掌握状态

## 0. 结论先行

LearnFlow 当前缺少的不是更多搜索工具，而是一条统一的“领域知识供给链”。领域知识必须先于教学规划进入系统，并能在对话中按缺口动态补充；讲义、练习、解释和验证应消费同一个带来源、版本、覆盖范围和时效状态的知识上下文。

DeepTutor 最值得借鉴的五点是：

1. **领域知识与学习者知识明确分离后再融合。** 课程知识回答“这个领域教什么”，学习者记忆回答“这个人现在需要什么”；两者在每个 Agent 步骤前按角色装配。
2. **知识准备不是把全文塞进向量库。** 论文把材料拆成原子单元，同时建立概念关系图和语义索引，以覆盖精确结构问题与模糊概念问题。
3. **先调查和规划，再写教学内容。** 个性化解题先分解问题、联合检索领域证据与学习者证据，再执行和写作；个性化出题也先决定“考什么”，再生成并独立验证“怎么考”。
4. **动态研究是知识补充通道，不是默认替代教材。** Deep Research 可以在调查中注入新子题并联合知识库、网页、论文和代码工具，但它仍应把结果回到共享知识上下文和可追溯引用中。
5. **知识库需要生命周期。** 官方仓库已经提供版本化索引、GitHub/文档站同步、hash diff 和来源漂移提示。这部分比单纯 RAG 更接近 LearnFlow 对“准确、时效”的需求。

DeepTutor 也没有完全解决问题：论文的量化核心主要基于预先构建的教材和论文知识库；时效性、真实长期学习效果以及主动层的长期收益没有得到同等强度的验证。因此 LearnFlow 应借鉴其架构原则，但不能把“接入 RAG”视为领域知识问题已经完成。

## 1. 问题域地图

```text
学习者提出目标或问题
├─ 领域对象是什么，而不是用户操作句是什么
├─ 哪些知识是稳定基础，哪些依赖版本或日期
├─ 用户已有或信任哪些教材、课程、文档和经验
└─ 当前证据覆盖了哪些概念、关系、例子和验证方式
                 │
                 ▼
预先准备的领域底座
├─ 原子内容单元
├─ 概念、前置、因果、例子、误解关系
├─ 语义检索
├─ 来源、版本、适用范围和更新时间
└─ 课程/项目/用户的权威偏好
                 │
                 ▼
对话内动态补充
├─ 覆盖缺口触发检索
├─ 时效要求触发更新
├─ 来源冲突触发对照
├─ 用户补充、固定、拒绝或替换来源
└─ 新证据先进入候选区，不直接成为课程真相
                 │
                 ▼
任务级 Domain Context Packet
├─ 学习主题与边界
├─ 必须覆盖的关系
├─ 可用证据与引用
├─ 未解决缺口和冲突
├─ 时效状态
└─ 对当前学习者的教学提示
                 │
                 ▼
解释 / 讲义 / 练习 / 验证
```

## 2. DeepTutor 的核心设计

### 2.1 静态知识不是模型常识，而是课程上下文

论文把课程材料分解成原子内容单元，并使用两种互补索引：

- 知识图表示定义、定理、例子等对象之间的结构和概念关系；
- 稠密语义索引处理表达模糊、关系隐含或学习者措辞不标准的问题；
- 两路候选使用 RRF 融合、去重并受上下文预算约束，形成领域上下文 `C_rag`。

工程含义是：检索目标不是“找几段相似文字”，而是恢复完成当前教学动作所需的知识结构。

### 2.2 领域上下文与学习者上下文在规划前融合

DeepTutor 把领域知识 `C_rag` 与学习者记忆 `C_mem` 分开维护，在每个 Agent 步骤前装配。规划者、写作者和出题者只得到与其职责相关的切片，避免所有信息无差别塞入上下文。

这意味着个性化不应只影响最后的语气。学习者的已知缺口、历史路径和有效讲法应该在：

- 选择调查问题；
- 选择证据；
- 决定讲解顺序；
- 决定练习角度；
- 决定支架强度；

这些上游阶段生效。

### 2.3 教学内容生成必须分离竞争任务

DeepTutor 的解题链是：

```text
Personalized Investigation
→ Step-by-Step Solving
→ Evidence-Based Writing
```

调查负责分解问题和取证，执行负责解决子问题与按证据重规划，写作只负责形成适合学习者的表达。三者分开，是因为它们争夺同一个上下文预算，混在一次生成中容易牺牲调查深度或呈现质量。

出题链同样分成：

```text
Idea Generation：决定考什么、为什么适合这个学习者
→ Critic-Guided Generation：生成题目、答案和解析
→ Independent Validator：独立检查事实、结构与计算
```

这直接对应 LearnFlow 当前“空讲义仍能生成结构正确的练习”的问题：对象结构正确不能替代领域内容正确。

### 2.4 动态补充采用调查工作流，而不是无限开放工具

论文的 Deep Research 先重写问题并分解主题，再由多个 ResearchAgent 使用知识库、网页、论文和代码工具调查。管理者可以根据中途证据注入新的子主题，最后按 comprehensive、focused、comparative、exploratory 四种认知目的形成输出。

可借鉴之处不是“让 Tutor 自由使用所有工具”，而是：

```text
发现知识缺口
→ 进入有预算的研究工作流
→ 新证据经过来源与覆盖检查
→ 回灌任务级知识上下文
→ Tutor 继续原教学动作
```

### 2.5 工程仓库补上了论文较弱的知识生命周期

官方仓库目前声明：

- 多种知识库引擎可以承载不同检索需求；
- 重建索引写入新的 `version-N`，保留旧版本；
- GitHub 仓库和文档站来源支持按 branch、glob、crawl budget 跟踪；
- 同步使用 hash diff 识别新增、变化和删除；
- Book 通过知识库 fingerprint 标记来源漂移；
- 写作修改以可接受/拒绝的 diff 落地。

这些机制说明“知识是否新鲜”需要显式版本和漂移状态，不能靠每次临时搜索猜测。

## 3. 跨系统共性问题

| 共性问题 | 典型失效 | 需要的系统能力 |
|---|---|---|
| 意图与主题混淆 | 把“用讲义带我学”当成领域概念 | 结构化学习目标与产物意图拆分 |
| 领域知识和学习者知识混淆 | 把学习者曾说过的话当课程事实 | 两类权威分离，任务级只读融合 |
| 有来源但没有知识结构 | 相似段落很多，却缺前置、因果和例子 | 原子单元 + 关系索引 + 语义索引 |
| 先写后找 | 内容已经生成，检索只负责补引用 | 调查和取证必须发生在规划、写作之前 |
| 静态库覆盖不足 | 新版本、当前事件、边缘主题无法回答 | 覆盖缺口与时效触发的动态研究 |
| 动态搜索无边界 | 每轮到处搜索，延迟高且来源漂移 | 触发条件、查询预算、来源等级和停止条件 |
| 来源存在但引用失去作用域 | 历史引用跳到当前打开的另一材料 | 引用绑定 material/version/locator/turn |
| 检索成功但没有有效证据 | query echo、错误 chunk、无关系片段 | 检索可用性和声明覆盖的独立验证 |
| 结构合格但语义为空 | 模板字段齐全，领域概念为零 | 领域覆盖、关系、例子、可验证性门禁 |
| 过时内容无状态 | 旧文档继续驱动讲义和练习 | effective_at、retrieved_at、fingerprint、stale 状态 |
| 教材与外部资料冲突 | 新标准和课程教材说法不同 | 冲突并存、作用域裁决、用户确认 |
| 教学产物各自找知识 | 解释、讲义、练习依据不一致 | 共享版本化 Domain Context Packet |
| 评测只查格式 | 空讲义也通过 schema 与流程检查 | Source Faithfulness、Groundedness、Logical Depth 等语义指标 |

## 4. 对 LearnFlow 的架构决策建议

### 决策 A：领域知识不进入五核 Knowledge 权威

五核 `knowledge` 表示“学习者对概念理解到什么程度”，不能同时承担“这个领域本身有哪些事实”。否则课程事实与学习者状态会互相污染。

建议复用现有 `Source / Chunk / Checkpoint.learning_contract.knowledge_input_contract`，在 Learning Design 边界增加一个版本化只读投影：

```text
DomainKnowledgePacket
├─ subject_key
├─ task_topic
├─ scope_and_non_goals
├─ concept_units
├─ relations
├─ examples
├─ misconceptions
├─ evidence_refs
├─ coverage
├─ freshness
├─ conflicts
└─ unresolved_gaps
```

它不是新的长期画像，也不写 KernelState。正式作答仍通过 Attempt 和 EvidenceEvent 改变五核。

### 决策 B：建立三层知识供给，而不是一条 RAG 管道

```text
Foundation Layer
  经策展、版本化的教材/标准/官方文档/领域图

Task Working Set
  当前项目、当前资料、当前用户选择和任务级检索结果

Live Supplement
  因覆盖、时效或冲突触发的网页/论文/仓库动态证据
```

三层合成时保留来源层级，不能把网页候选自动晋升成课程权威。

### 决策 C：让用户参与知识寻找，但不把检索责任推给用户

用户可进行四类轻操作：

- 指定：选教材、课程、官方文档或项目资料；
- 补充：上传文件、URL、选中文本或说明自己的经验；
- 裁决：在冲突来源之间选择本课程/本项目采用哪一版；
- 反馈：标记资料过时、不相关、太难或确实有启发。

系统仍应先主动发现覆盖缺口并提出少量高价值候选，而不是要求用户自己从零找资料。

### 决策 D：用 Harness 决定何时补知识

建议触发动态补充的确定性信号：

1. 当前 DomainKnowledgePacket 覆盖不足；
2. 用户明确要求最新、版本、政策、价格、论文或行业现状；
3. 已有来源超过领域 freshness policy；
4. 两个高权威来源冲突；
5. 生成器需要的概念、关系、例子或验证依据不存在；
6. 用户指出内容错误或过时。

模型可以提出查询候选，但搜索深度、来源等级、停止条件和能否发布由 Harness 决定。

### 决策 E：讲义与练习共享同一内容 brief

```text
DomainKnowledgePacket
→ TeachingContentBrief
   ├─ 必讲关系
   ├─ 前置与边界
   ├─ 例子规格
   ├─ 常见误解
   ├─ 练习目标
   └─ 来源闭包
→ Lecture candidate
→ Practice candidate
→ 独立语义验证
→ publish
```

这样可以防止讲义讲 A、练习考 B，也能在来源更新后准确识别哪些产物需要重建。

## 5. “准确、时效、启发”应成为独立维度

| 目标 | 最小可检查条件 |
|---|---|
| 准确 | 关键声明可回到具体来源；计算和答案独立验证；冲突不静默覆盖 |
| 时效 | 来源带版本、时间与适用期；过期策略按领域定义；更新后能标记受影响产物 |
| 启发 | 不只返回事实，还恢复前置、因果、对比、反例、误解和可迁移问题 |
| 覆盖 | 当前教学目标需要的概念、关系、例子、练习依据均有状态 |
| 可教 | 难度、表征和支架适合当前学习者，但不篡改领域事实 |
| 可验证 | 讲义中的内容足以推出练习答案，练习又能验证目标关系 |
| 可纠正 | 用户能指出错误、替换来源、回滚版本并重新生成受影响产物 |

## 6. DeepTutor 的证据边界

需要明确区分：

- **论文已量化验证：** 基于 30 个知识库、五个领域、270 个交互任务的个性化解题与出题；移除 RAG 后 Source Faithfulness 和练习 Groundedness 明显下降。
- **论文给出架构但未充分量化：** Deep Research、Guided Learning、TutorBot 和长期主动陪伴。
- **官方仓库当前实现：** 多引擎知识库、版本化索引、来源同步、fingerprint 漂移检测、共享上下文。
- **公开工程问题提示的风险：** 大库检索延迟、模型工具调用兼容、历史引用错绑材料。Issue 只能作为真实风险样例，不能推断所有部署都会失败。

论文评测也没有把“时效性”设为独立指标；其 Source Faithfulness 和 Groundedness 主要衡量对给定材料的忠实。因此 LearnFlow 若面向软件版本、政策、行业和研究前沿，必须另建 freshness eval。

## 7. 反模式

- 把用户整句请求当领域主题。
- 没有知识输入时用通用模板冒充讲义。
- 先生成正文，再用搜索给已有结论补引用。
- 只验证 JSON/schema，不验证领域内容。
- 把检索到的网页直接写成知识核状态。
- 每个 Skill 自己维护一套来源和检索规则。
- 用一个全局“最新”阈值处理数学定理、软件 API、政策和新闻。
- 让模型在没有 Harness 预算与来源门禁时自由扩张工具调用。
- 只记录 URL，不绑定版本、locator、检索时间和支持的 claim。
- 来源过期后静默重建讲义，导致练习和历史解释不可复现。

## 8. 概念卡与晋升建议

| 概念 | 一句话定义 | 反直觉点 | 对 LearnFlow 的 diff |
|---|---|---|---|
| Hybrid Grounding | 每步同时消费领域知识与学习者证据 | 个性化不是替代领域准确性 | 当前两条上下文链未在讲义生成前稳定汇合 |
| Dual Retrieval | 关系检索与语义检索互补 | 相似段落不等于恢复知识结构 | 当前 Source/Chunk 主要缺关系级覆盖 |
| Investigation First | 先分解、取证和规划，再写作 | 更长 Prompt 不能替代前置调查 | 当前微学习把调查、生成、验证压成一次调用 |
| Shared Evidence Closure | 讲义与练习共享同一证据闭包 | 两个各自正确的产物也可能彼此不一致 | 当前练习可由 fallback 独立生成 |
| Knowledge Freshness | 来源的新旧是可计算状态 | “权威”仍可能对当前版本过时 | 当前缺少按领域的 freshness policy |
| User Knowledge Curation | 用户参与选择和纠正课程来源 | 用户协同不等于让用户负责检索 | 当前资料可附加，但缺少冲突和权威裁决体验 |

这些概念彼此耦合，应先晋升为一个产品级 `domain_knowledge_supply` Playbook，而不是拆成多个模型 Skill。只有其中“如何审计一个教学任务的知识供给”在跨场景稳定后，才适合晋升为 Codex/Agent Skill。
