# 学习路径图库与视觉规划入口修复

## 失败分析

用户截图显示 `visual_teaching_brief_invalid`，同时缺少 explanation、identity、objects、state、changes。这是在 `parseVisualTeachingBrief` 的规划协议检查阶段，尚未进入确定性计算或 SVG 渲染。截图没有保留原始模型 JSON，因此不能断言具体漏了哪些顶层键，也不能证明模型不会解释 CNN。

代码确认两个工程问题：

- Node 的视觉规划请求继承 `buildTutorInstructions`，其中 system 要求“最终只输出面向学生的教学正文”；同一次请求的 user 却要求 JSON。还继承插件指令、Tutor 工具消息和末尾教学指导。这是角色和输出合同冲突。
- Authoring 的完整例子展示内层 VisualSpec，却由解析器消费外层教学 Brief。直接照抄例子会缺少外层身份信息。一次重试会继续承受相同角色冲突。

修复：Web 与 Desktop Node 入口采用共同的视觉规划 system；仅附当前会话最近四条 user/assistant 消息作为明确标记的数据，各条最多 5000 字符并标注省略量；主题锚点继续独立传递，失败工具轨迹和插件指令不进入规划器。视觉调用不追加 Tutor 阶段指导。补充外层根对象例子，明确最小 Spec 必须放在 visual_spec 内。保留严格校验和最多一次真实错误修复，不以放宽字段、文本占位或强制选模板掩盖失败。桌面同步短追问主题识别和 8000 token 输出预算。

这不说明上下文越少越好：当前问题、主题锚点、近期讲解、能力目录、维护作品边界和真实校验错误仍需保留。下一步模型比较应固定这些输入，在相同入口比较成功率；不能先把工程冲突归因于模型。

每个条目提供中文/英文别名、典型学生问题、课程稳定 ID 与标题、前置知识、适用目标和不适用边界。catalog 同时索引题名、别名、标签、描述、问题、课程 ID/标题，并将完整有界元数据返回给 Agent。返回最多五个候选；命中只是候选，Agent 可选原版、改编或从零组合。明确从零请求仍禁用模板；自动生成不会自动发布入公共库。

新增十个作品为人工固定数据分镜，含数组、关系图或时间线和状态表。运行时验证为 `illustrative_authored_sequence`，仅保证绑定/结构，不宣称验证了领域算法真值。需要更改数值或运行任意输入时必须改编或使用注册计算模型。已维护计算型作品继续通过原有确定性模拟器和独立检查。
