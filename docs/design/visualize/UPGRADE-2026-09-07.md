# 可组合图解与动画工具

本轮目标：维护作品库与从零生成并行，统一编译、验证、交互和 Tutor 回流。原交付包仍是设计来源；三个参考输入是基线，不是生成能力白名单。测试按用户要求集中在少数黄金案例，同时检查跨端契约和构建。

## 创建与复用

当前图解/动画入口保持不变。Harness 先按已解析的对话主题读取宿主能力目录与维护作品候选，再让 Learning Design 选择合适作品、修改作品副本或直接生成新 Spec。未检索到作品不意味着能力不支持。“从零生成/不要模板”绕过作品选择，但仍使用相同受控原语和计算规则。

`POST /api/visuals/catalog` 接受 query、kind，返回已安装能力、教学模式与最多五项作品摘要。候选评分仅用于召回，不自动把用户输入换成教学示例。`POST /api/visuals/template` 按 id+version 返回维护 Spec、内容摘要和经验证的默认运行范围。两者要求当前宿主认证；不读取任意路径，不允许模型发布或修改共享作品。

作品数据位于 `packages/learning-core/src/learnflow_core/visuals/library/`，在 Python wheel、容器和桌面 sidecar 中一起发布。维护作品和新生成 Spec 均调用 `compile`。compile 可附 template_ref，由服务端对比内容摘要返回 maintained_library、adapted_library 或 generated 来源；来源不替代计算正确性验证。修改用户参数从 s0 计算新运行，保存旧参数实验可供对照。

## 表达与计算

VisualSpec 0.1.0 保持兼容，0.2.0 增加有方向关系、矩阵窗口与计算掩码、表格、时间轴、对象可见性、教学模式和可组合模型。旧 schema 不静默升级。

- `computation.pipeline`：有限的注册运算序列，参数可引用数据、控件和此前完成的结果。每个运算明确 shape、类型、边界和计算约定，不执行自由 Python、JavaScript、包安装或表达式字符串。卷积等运算产生逐窗口状态，结果字段在计算完成后才进入后续步骤。
- `structure.sequence`：用于从整体到局部的分解、概念关系、已声明的流程示意。验证结构、引用和资源边界；明确显示为作者编排的示意，不能冒充算法证明、协议模拟或数值验证。
- 原有 BFS、二次型梯度下降、均匀分布区间继续提供可计算模型。相同图元、状态快照和交互协议跨模型复用。

新知识点优先组合已安装操作和原语；缺少计算语义时扩展有版本的操作，而不是复制专用页面或虚构模型名。高阶自由代码、3D 与视频仍按原包的可选扩展处理，不把任意媒体生成作为本轮图解工具的前提。

## 教学作品维护

每份维护作品包含稳定 id、版本、标题、别名、目标、模式、假设、适用形式与完整 Spec。维护步骤：核对教学目标和参数来源 → 编写组合配方 → 检查默认/重要边界运行 → 查看图形与数据替代 → 更新版本 → 随代码发布。已有版本内容不得被静默替换。生成产物留在学习者自己的对话中，未经维护流程不进入公共作品库。

CNN 维护作品采用合成像素和明确的未训练权重，展示卷积、ReLU、池化、全局平均、线性分数和 softmax；不能把教学输出宣称为 MNIST 识别准确率。TCP 作品是正常握手的消息/状态示意，未声称实现超时、丢包或完整 TCP 状态机。

## 失败与回流

unsupported、needs_clarification 与格式错误分开；能力缺失不走同样的格式修复循环。真实编译错误参与有界修订，模型获得具体字段/操作诊断。可保留讲解，但失败原因必须可见，不能统一说“稍后重试”。

图形局部拥挤优先重排/换行；仍无法容纳时显示完整当前数据。用户选择对象、参数、步骤和快照一起回流 Tutor；旧请求不能覆盖新状态。下载的 SVG 与 JSON 保留当前参数、步骤与验证范围。操作与浏览不升级掌握度，既有确定性预测事件仍是零 Kernel target。

Contract impact：registry 2026-09-07.1，新增 visual_content_library 与只读 retrieve_learning_visual；新 VisualSpec 0.2.0 命名空间及 catalog/template 内部 API。三类 Agent、五核与旧事件语义保持不变，无数据库迁移。维护库、界面与生成编排均有 Web/桌面消费者。


## 验证与使用

内容黄金集中在维护 CNN、多阶段 TCP 和库外矩阵组合，沿用旧 BFS/GD/密度基线作为兼容检查。`frontend` 的 `npm run test:visuals` 覆盖共享渲染及编排；Desktop 同名命令覆盖其宿主适配。两个后端运行 `test_visualize_composition.py`、`test_visualize_runtime.py`、`test_visual_planner.py` 和架构注册检查。没有扩展成全领域内容测试矩阵。

浏览器黄金使用真实后端编译 bundle 的隔离界面：CNN 42 帧与 TCP 4 帧在 720/300 宽度检查，选择对象与快照追问、滑块重算、按运算阶段对齐参数对照、刷新恢复、SVG/JSON 导出、390px 手机界面均通过。多状态图解也能逐步查看，只有动画提供自动播放。模型生成走独立合成输入，不使用或修改真实用户对话。

发布资源检查覆盖共享 wheel（两份 schema、五份作品、operations 模块）和 macOS arm64 sidecar 构建；没有安装替换用户应用或迁移数据库。Web/Desktop 前端构建与跨端共享契约检查通过。全仓测试和 seeded demo 未执行，本轮按少数黄金案例及受影响契约验收。

真实模型测试发现并修复了默认推理耗尽输出预算的问题：视觉 JSON 规划对官方 DeepSeek V4 使用非推理请求，普通 Tutor 模式保持不变；供应商 length/empty/incomplete 错误直接终止，不冒充 JSON 格式错误进入修复。结构化校验一次返回多个有界错误位置，作者上下文明确 ID、检查点、当前视图与注册输入字段，避免一次修复只补一个字段。


最终真实模型黄金：CNN 省略主题的追问一次检索到精确维护版本，生成 42 帧；明确“不要模板”的 A=[[1,2],[3,4]] 请求一次从零生成 transpose → matmul → flatten → softmax，约 9.2 秒、12 帧，无修复与模板读取。输入保持原值，C=[[10,14],[14,20]]、展平和概率归一化核对通过。计算型步骤的操作说明及通用输入/输出/右侧矩阵角色由注册规则生成；动态矩阵的高亮按角色绑定，矩阵乘法左右分别标出行与列（binding_policy=registered_operation_roles），模型的教学补充留作 authored_note，不作为数值验证的结论。

最终检查结果：Web 后端 41 项、Desktop 后端 40 项受影响检查通过；视觉前端黄金 Web 15 项、Desktop 11 项通过；两端构建、共享契约、sidecar 构建和 diff 检查通过。真实生成的库外 12 帧、维护 CNN 42 帧、TCP 4 帧在最终编译器与渲染器的 720/300 宽度再次检查，无渲染诊断。按仓库当前本地重构边界，本轮不推送、不部署。
