# 记忆系统长尾优化实验报告

本轮将上一份报告第 9 节的五项建议落实到共享只读检索层：查询归一、带来源的原文片段、时间候选配额、有界二跳图扩展、条件式摘要与未覆盖处理。实现版本为共享核心 **0.2.3 / relevance-budget.v2**，Web/Desktop 共同消费。

**结果口径：这是合成检索组件实验。** 固定回归集上的目标覆盖提升，不等于真实用户回答正确率、学习效果或未见任务泛化。运行直接使用真实检索代码；没有调用 LLM，没有用模型裁判替代确定性评分，也没有把人工构造的投影写成真实学习事件。

## 1. 实现范围

| 优化 | 本轮完成内容 |
|---|---|
| 查询归一 | NFKC、大小写归一、11 组可审计术语别名；在过滤后的词表中采用唯一单编辑/换位纠错；歧义与标识符拒绝改写 |
| 原文与例外 | 目标句段与远处限定共同入包；640 字符以内，保留 Fact ID、完整正文 SHA256、原文偏移和未装入限定计数 |
| 时序多样性 | 历史请求为同主题 active Facts 提供最早、中间、最新候选；当前纠正锚点单独处理 |
| 图扩展 | 仅 BLOCKS/ENABLES 最多两跳，每跳过滤，循环剔除，前缀与后续边共同预算；公开窗口、分支和遗漏统计 |
| 条件摘要 | 汇总任务保留 Module/Claim，细节优先 Fact；移除弱相关背景，并标记没有直接入包事实 |

没有实现 embedding 语义通道、无限图搜索、全历史分页或模型控制记忆等级。权威链、三类 Agent、五核、EvidenceEvent schema 和数据库结构保持原有契约。完整参数与兼容性见[实现说明](../implementation/MEMORY_LONG_TAIL_RETRIEVAL.md)。

## 2. 实验设计和可复核证据

主实验复用上一轮冻结的 35 类场景、6 条合成轨迹（2001–2006）、210 个查询。其中 162 个有明确目标证据，另外包含 Human 适配与未覆盖/隔离控制。数据规模为 13,892 Facts、18 Modules、18 Claims、738 Edges；历史长度为 256/1,024/4,096，每档两条轨迹。

Fixture 与 gold SHA256：`4ad2a0de803f7282bf5ce8e31a0b04dc39b719ae53183e1a72b98aca7ce50792`。版本、场景、评分器、6 个消融配置、1800/2800/5600 预算、每条件两次重复均保持。每端 3,780 条件、7,560 次读取；重复只检查确定性，不增加独立样本数。旧版结果来自上一轮封存的 relevance-budget.v1，未重算或改写旧分数。

v2 场景已被用于诊断并指导本轮优化，因此属于**已知回归集**。另有 TCP/scheduler/deadlock、远处限定、304 条同主题历史和隐藏中间节点等独立 fixture 的开发回归；这些也不是盲测。纯边机制实验使用另一组查询，单独汇报，不混入主表。

协议见 [PROTOCOL_LONG_TAIL.md](../../scripts/evals/memory_retrieval/PROTOCOL_LONG_TAIL.md)。原始包、逐查询分数、fixture/gold、多文件 hash、命令、开发失败记录随证据目录保存。冻结运行的检索源码 SHA256 为 `3f34a008a75a047751e94a2b4b05e66e20a3b71c64b88e622032b268806ce021`。

## 3. Web 主实验结果

覆盖率是每个查询召回的目标单元比例；完整率是召回全部目标的查询比例；精确率是已匹配目标单元占所有可见已标注单元的比例。额外的真实背景也会进入精确率分母，所以该指标表示对标注目标的聚焦程度，不是事实真伪率。三项主指标分母均为 162 个有目标查询。

| 内容预算 | 旧完整系统覆盖率 | 新完整系统覆盖率 | 旧完整率 → 新完整率 | 旧精确率 → 新精确率 |
|---:|---:|---:|---:|---:|
| 1,800 | 82.10% | 100.00% | 77.78% → 100.00% | 26.41% → 58.22% |
| 2,800 | 85.19% | 100.00% | 85.19% → 100.00% | 23.46% → 42.07% |
| 5,600 | 85.19% | 100.00% | 85.19% → 100.00% | 21.39% → 34.75% |

2,800 预算下各配置：

| 配置 | 覆盖率 | 完整率 | 标注证据精确率 | 平均内容体估算 token |
|---|---:|---:|---:|---:|
| full | 100.00% | 100.00% | 42.07% | 1,861.52 |
| facts_only | 99.07% | 96.30% | 42.09% | 1,860.15 |
| no_head_cache | 100.00% | 100.00% | 42.07% | 1,861.52 |
| no_kernel_routing | 92.90% | 92.59% | 41.05% | 1,869.04 |
| no_relations | 96.30% | 92.59% | 40.05% | 1,830.31 |
| recent_facts | 5.56% | 3.70% | 5.49% | 733.94 |

`facts_only` 只消融 Module/Claim，仍使用本轮同样的查询归一、分段、时序及事实间图机制；不能把此表当作五项改动各自的因果贡献。`no_head_cache` 是重建缓存读取，不是删除头部内容。

## 4. 长尾收益、误召回与退步

在 2,800 预算下，每个下列 family 均有 6 个查询：

| 场景 | 旧覆盖率 → 新覆盖率 | 旧精确率 → 新精确率 |
|---|---:|---:|
| 精确中文词：振荡器温漂 | 100% → 100% | 100% → 100% |
| 英文大小写 | 100% → 100% | 100% → 100% |
| 同义术语：MVCC | 0% → 100% | 0% → 100% |
| 错拼：semaphroe / fairnes | 0% → 100% | 0% → 100% |
| 长文尾部关键句 | 0% → 100% | 0% → 100% |
| 大量同主题历史中的最初待办 | 0% → 100% | 0% → 12.50% |
| 直接一跳返回条件 | 100% → 100% | 50% → 40% |
| 汇总 bundle | 100% → 100% | 94.44% → 90.74% |

同主题历史仍带回其他时间段；直接一跳查询会带入更远的依赖；汇总可能带入额外背景。这些收益与退步均保留，没有只取成功截图。长文尾部的 gold 只包含关键尾句；远处限定保留由单独的原文重建测试验证，不能用尾句覆盖率声称所有长文本限制都已保留。

未覆盖场景的原始包检查覆盖 items、paths、非 Human 头部正文与概念节点：三个预算下均从旧版 **6/18 真正为空**，提升到新版 **18/18 真正为空**。Human 的有 scope 教学控制投影可以继续存在。额外开发测试覆盖歧义错拼、两次编辑、数字/下划线标识符，拒绝把这些近似字符串当成相关证据；样本有限，未估计真实语言分布的误召回概率。

完整系统与 facts_only 的优势取决于场景。汇总 bundle 中 full 覆盖 100%，facts_only 覆盖 75% 且没有一个查询完整；但同义、错拼、长文尾部两者都为 100%。汇总的内容体估算为 full 2,746、facts_only 2,678；带例外的局部细节为 full 2,642.67、facts_only 2,662.83。不存在“所有任务都固定多塞一层更好”的实验结论。

## 5. 成本与限制

2,800 预算的 Web 对照：

| 成本口径 | 旧 full | 新 full |
|---|---:|---:|
| 内容体平均估算 token | 2,085.39 | 1,861.52 |
| 完整返回包平均估算 token | 2,603.16 | 2,860.78 |
| 检索中位延迟 | 33.08 ms | 81.23 ms |
| 新版 p95 延迟 | — | 124.41 ms |

新增查询审计、来源与图统计让完整包估算增加 **9.90%**，而内容体减少约 **10.73%**。token 均使用同一 JSON 字符估算器，不是模型 tokenizer 或真实账单。产品预算仅覆盖 heads/items/paths/概念图/指导，manifest/omitted 等外壳不在该预算中；“预算检查通过”不能被解释为整段 API JSON 不超过标称 token。跨日期、本机不同运行状态的延迟只作描述，不能归因于某一个优化。

图仍有 24 根、32 前沿、每根 4 个二跳分支、768 incident 候选行限制；每个根与关系类别选择近期 6 条和最旧 2 条。旧边配额可能恢复最旧必要条件，未承诺恢复中间所有边。`max_depth_found` 是候选发现深度，最终是否入包需检查路径；片段太长、限定太多时也可能省略，已公开计数。

别名表只覆盖有限计算机术语；没有向量语义检索。时间配额只覆盖 active Facts，不能代替完整历史审计。覆盖分不评价路径方向推理、生成回答或教学策略，也不代表已证明每个未见场景安全。

## 6. 双端、纯边与发布证据

双端 3,780 个相同条件的全部非计时指标一致，7,560 对完整 ContextPacket 零差异；缓存重建配置与 full 的非计时结果也零差异。两端各预算/配置均为零已检测违规、零内容体预算失败、零重复不稳定。Desktop full 在 2,800 预算下中位延迟 82.71 ms、p95 134.29 ms，效果指标与 Web 一致。Web/桌面分别核对了 192/199 个源码与协议文件，运行前后 hash 未变。

纯边探针只用“仪器联调”或“密集”召回根节点，目标没有查询词；分别设 max_hops=0/1/2，每组 6 轨迹 × 2 场景 × 3 预算 × 2 重复 = 72 次。三个预算下结果相同：

| hop 上限 | 两跳链目标覆盖 / 完整率 | 96 条边中最旧目标覆盖 / 完整率 |
|---:|---:|---:|
| 0 | 33.33% / 0% | 50% / 0% |
| 1 | 66.67% / 0% | 100% / 100% |
| 2 | 100% / 100% | 100% / 100% |

逐包附加检查确认二跳目标出现在 `relation_paths` 的 hop=2 通道，未被 items 直接词法召回，且完整首跳前缀在包内。密集探针只验证预先指定的最旧边，不能外推为对全部 96 条边都能检索。完整主实验加探针共 **15,336 次本轮正式读取**，另有 420 次开发试跑；两类数据分开保存。此次纯边探针用 Web 宿主运行，Desktop 的对应机制另有同文件黑盒回归，未冒充也跑过一遍 Desktop 纯边统计实验。

隔离副本的 `start.sh demo` 实际启动成功：`/demo` HTTP 200、`/api/demo/status` enabled=true、`/api/architecture/validate` valid=true。没有使用日常数据库。云端发布版本另见后续发布记录。
