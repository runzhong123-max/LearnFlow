# 教育记忆升级与同场景复验

本轮修复了两处教育链路缺口：普通概念题不再因“不同题目 ID 答对”升级稳定掌握；已经送达的当前时间、支持需求、知识卡点和受助反馈开始约束真实计划。**在固定的教育开发场景中，两端完整配置在 3,200 预算下的规划采用从 8/24 提高到 20/24，画像形成从 284/300 提高到 288/300。** 正向信息交付仍为 88/104。本轮主要改善消费者和证据门，没有把读取层提升与规划提升混为一谈。

这是合成轨迹的契约检查，不是学生画像准确率、真实学习收益或盲测成绩。旧报告和原始失败保留，新增反例不并入原实验分母。

## 1. 实际更新与兼容边界

Contract impact：共享核心 `0.2.4`，Web registry `2026-09-08.8`、Desktop `2026-09-08.8-desktop`；策略为 `concept-evidence.v2` 和 `learning-plan-guidance.v1`。事件和计划 v1 增量兼容，三类 Agent、五核和唯一证据链不变，没有数据库迁移或历史回填。设计和代码边界见 [教育记忆策略](../implementation/EDUCATION_MEMORY_POLICY.md)。

- **掌握证据**：普通正确且独立的作答仅保留 `verified_once`；受助成功与帮助未知分别保留。重复题面换 ID 或同会话做多题不能产生 checkpoint stable。服务端记录实际作答角色和策略版本。长期稳定仍使用原有间隔复习与审核变式门，显式迁移路径保持独立。
- **规划采用**：对经过 scope、期限和取消过滤的指导编译确定性约束；时间上限、分小步、当前卡点、渐进撤提示和当前目标作用于离线结果、模型候选、已确认候选以及重规划。模型不能扩大有效时间预算、取消必需验证或把验证排到准备之前。
- **细节与生命周期**：当前卡点只从同一来源事件的已选 Fact 保留具体正文与来源；已解决卡点不被旧事实复活。重规划保留已经完成的阶段，把新指导放入未完成阶段。临时时长到期可以恢复原估计，用户手动编辑时长则更新重规划基数。

1–4 分钟代表本次推进一个微步骤，剩余阶段留待后续，不意味着整个任务能在该时间完成。规划文本和任务完成也不成为掌握证据。

## 2. 保持不变的实验设计

固定使用 `education-memory-ablation.v1`。`run.py`、`verifier.py`、`PROTOCOL.md`、`test_verifier.py` 与上一轮两端归档逐字节一致；未改题面、操作轨迹、预算、gold 或判分。修复发生在新的冻结版本中，运行时不改被测代码。

数学分数比较、物理串联电路、编程递归终止、生物光合作用各一条轨迹，覆盖学习起点、明确困难与解决、时间与支持变化、长期偏好/本次覆盖/取消、目标确认、错误—受助重做—变式—间隔复习、原题复制、来源审计与跨范围负例。每条 41 个观测点、32 条课堂历史干扰；每端 164 个观测点、288 次操作，7 配置 × 2 预算 × 2 重复，共 4,592 条 trial，双端 **9,184 条**。

形成层每端 300 条判据；每个配置/预算有 104 条正向交付、40 条排除和 24 条规划采用判据。重复只检查确定性，四种题面不是独立总体样本。API 函数接收隔离身份，正式评估入口实际产生 Attempt、事件、Mutation 和记忆；没有伪造正确结果或完美摘要。业务时间模拟推进，所有模型关闭、实验进程拒绝网络、SQLite 位于临时目录。

配置定义保持旧报告：facts_only 同时移除 Module/Claim 及其纠正锚点作用；recent_facts 只留最近 24 个 Fact；no_relations 只消融返回路径，其他图索引仍在；no_guidance 移除指导但保留另一个 adaptation 通道；no_memory 给真实规划器空画像。完整配置与事实配置的差异不能直接归因于“摘要推理”。

两端结果分别运行、记录和复算。下表使用单端分母，箭头为旧版 → 本轮；2296 个跨端对应条件中，判定差异 0，教育语义 hash 差异 0。

| no_memory | 0 → 0 | 0 → 0 | 0 → 0 | 0 → 0 |

40 项排除检查在各配置/预算下均通过，单列而不合并成总准确率。画像形成改善来自四种课程的重复题 ID 探针；剩余 12 项失败仍是三种自然表达在四门课程中未形成绑定本次输入的目标指导。它们没有被删除或改成宽松判据。

在完整配置 3,200 预算的 24 项规划要求中，新增 12 项通过，来自明确 10 分钟安排、明确支持后缩短至 20 分钟、受助成功后的撤提示步骤，各四门课程。按逐条件逐判据比较，本轮 Web 的原有通过项退步 0 项；两端的完整变化清单见 `paired-update.json`，不只看净增量。

规划判据直接检查最终结构化时长和指定阶段/summary 的可见文本。因此它证明这些约束进入实际计划，不能证明后续 Tutor 每次讲解都执行、模型真实在线生成的质量或学生最终学会。

`analyze.py` 核验归档源码 hash、运行完成、trial 去重与交付/规划判据；新增只读 `compare_education_updates.py` 按条件键配对，核验完整笛卡尔矩阵、所有观测点和 gold，并从保存的 actual 复算形成、交付、规划的 passed 值。正式源码清单也与运行前后清单核对，避免新增文件漏出 hash 审计；Web 184、Desktop 191 个源文件均一致，零网络尝试、预算违规、重复/缓存语义差异或本轮定义的来源审计违规。

运行生成的 Claim ID 不属于固定题面：每端 6 处形成判据的 ID 因少写旧错误掌握 Fact 而顺移。比较器按完整 Claim 正文、verification_status、来源 Event 与 Fact 的 kernel/predicate/grade/正文/object 递归匹配；只对具名 claim_id 引用做身份归一，拒绝缺失、歧义或循环。原始 ID、状态预期和 actual 判分保持不变，映射逐项记录在 `paired-update.json`。另有独立只读审计脚本从操作输入与时间重新证明 Web 的 8 个 Claim 映射（其中 6 个 ID 变化），从 observed 重建每版 300 条形成判据，从包与计划重建 4,032 条可直接核验的判据；脚本和完整输出一并归档。

## 5. 失败记录与仍未解决的问题

- **中间版本确实退步过**：冻结提交 `a41f098` 的 Web 全规模运行已完成 4,592 条，发现具体知识卡点被通用准备文字覆盖。该批保留于 `previous-runs/v2`，未继续跑 Desktop，也不混入最终双端结果。修复为只保留与当前指导同一 Event 的已选 Fact，另加正反例；随后重新冻结、完整重跑。
- **自然表达与交付预算仍有限制**：“只剩10分钟”“今天只有1小时”“我今天很累，请放慢节奏”在所测输入入口上的形成失败仍保留。本次代码语言覆盖等指导仍可能被子预算裁掉。未交付的信息不会被新消费者凭空补出。
- **历史画像未纠正**：旧版本已经写入的 checkpoint stable、Fact、Module、Claim 没有迁移或删除，仍可能出现在已有用户画像中；本轮只防止新普通作答继续制造这一类稳定结论。
- **真实教育证据仍不足**：现有审核变式门没有证明语义新颖性或系统外答案暴露；无真实学生长期跟踪、教师独立标注或学习收益因果实验。在线模型仅有故意违约/超时的测试替身，不能称为实测在线模型效果。
- **浏览器演示未闭环**：隔离种子初始化、`/health`、`/api/demo/status` 和 `/api/architecture/validate` 已通过；CUA 实查 `/review`、`/demo` 均停在统一登录页，没有自动登录，浏览器教学操作未执行。不能写成完整 demo 通过，也未以此替代服务层测试。
