# 教育记忆与规划 v2：升级及消融实验报告

本文面向计算机专业群教学场景与比赛技术答辩。系统目标是从学习行为中形成有来源、可纠正的学习者状态，并据此调整下一步教学安排。它不能凭一次答对认定稳定掌握，也不能从错误推断人格或固定学习风格。

**结果状态：实现与完整离线实验已完成。** 最终 `formal-03` 共执行 65,820 个条件，覆盖校验通过，执行错误与运行中源码漂移均为 0。教师审核尚未进行，真实学习收益尚未测量；以下改善仅指本次固定数据上的工程和行为结果。

## 1. 升级解决什么问题

| 原问题 | 本轮实现 | 可以检查的行为 |
| --- | --- | --- |
| 任务正文、引用和本人要求混在一起，容易漏提取或误提取 | 局部语段解析，保留原始字符范围；区分题干、引用、假设、否定与本人要求 | 同一输入中拒绝题干里的时间，同时保留本人提出的时间限制 |
| 明确跨日安排按旧会话期限失效，或取消后仍残留 | v2 来源/应用 scope、显式截止时间、覆盖顺序和取消墓碑 | 规划重算时移除失效约束并应用剩余有效约束；无其它时长约束时恢复原估计 |
| 零散事实无法说明一次练习是否受助、是否重试 | 从真实已评分 Attempt 和完整事件链投影只读 learning episode | 原题重试不等于迁移；帮助未知保持未知；没有来源不拼造过程 |
| 读取组件是否发生作用不透明 | 有界 BM25 词法排序、独立开关与实际激活诊断 | 分开记录候选匹配、查询归一、入包、预算截断及证据交付 |
| 计划难以解释采用了哪条学习证据 | 确定性准备动作与 `teaching_decisions` | 动作引用已交付 Event；完成阶段保留；不会产生新的掌握认定 |

三类主 Agent 与五核权威不变。唯一写入链仍为 EvidenceEvent → reducer → KernelMutation → KernelState → Fact/Module/Claim。过程包是只读投影，计划决策说明也不是新的画像权威。详细兼容性见[实现说明](../implementation/EDUCATION_MEMORY_V2.md)。

## 2. 实验问题与数据

主问题是：在相同学习经历与预算下，记忆读取组件是否改变合法证据交付、明确约束落实和可追溯教学准备？这是工程与行为评测；教学适切性和真实学习收益需要另外验证。

| 轨道 | 数据与单位 | 本轮矩阵 | 解释边界 |
| --- | --- | --- | --- |
| 计算机教育 | 9 个方向、72 个任务族、22 种轨迹，1,584 个合成案例，216 道题目探针 | 12 组 × 2 个预算，共 38,016 条件 | 标签待教师审核；原 holdout 已被作者看过，不再是未见测试 |
| 通用长期记忆 | 固定官方 LoCoMo10，10 段对话、1,986 个问题 | 7 组 × 2 个预算，共 27,804 条件 | 只检索原始证据，不运行模型问答，不是官方准确率 |

教育每个案例通过真实服务入口形成一次，再在同一状态快照上读取各组。其中回答通过封闭候选评分 API 回放，不代表验证了开放式代码、SQL 或自由回答判分；不支持的原始操作继续保留 `adapter_gap`。LoCoMo不伪造学习评分事件来启动 episode。主类 1/2/4 的有效 1,438 题单独计分；外部知识类、对抗类和无效引用单独保留。旧测试集、gold、旧报告没有修改。数据来源与许可证见[原来源清单](../../evals/joint_memory/SOURCES.md)，干预和统计约定见[冻结协议](../../evals/education_memory_v2/PROTOCOL.md)。

预算为 1,800 / 3,200 个字符估算单位：对公开预算 JSON 的字符数除以 3.2 并向上取整。本轮计入 episode、诊断和组件策略。它不是精确模型 token、完整 HTTP 载荷、整个规划输入成本或真实 API 费用。

产品规划器的 `checkpoint_tutor` 默认预算为 2,900；正式消融主动覆盖为上述两个预算。发现这个差异后，另用同一冻结代码、同一教育案例和 full 配置补测默认预算，结果单列于 4.5，不混入原正式矩阵。

## 3. 消融解释规则

- `facts_only` 去掉 Module/Claim 及相关边，但仍保留 Fact 路径、教学控制和 episode。它检验的是这些层级移除后的系统行为，不是字面意义上只留下事实文本。
- `no_guidance` 在读取后裁去历史指导，保留当前输入控制，不重新填充释放的预算。其诊断里的 delivered 仍表示裁剪前状态，实际交付以裁剪后的列表为准。
- `no_episodes` 在构包前关闭过程投影，释放的预算可以用于其它证据；差值包含这个预算竞争效应。
- `no_bm25`、`no_aliases`、`no_fuzzy`、`no_temporal`、`no_summary_boost` 分别关闭对应组件。必须同时报告实际触发；没有触发不能证明组件无价值。
- `no_relations` 关闭输出关系路径，独立概念附件仍保留；`recent_facts` 还改变历史保留范围，只能作为受限基线。
- `no_memory` 仍保留当前明确控制。当前输入执行能力和跨会话记忆能力分别计分。

所有读取组共用新版输入形成过程，因此这不是解析器的独立因果消融。新旧全系统对比可以说明固定案例上的前后行为，但也包含新预算载荷及交付通道的变化。组件有替代关系，不能相加各组差值作为总贡献。

各记忆组还共用规划器的节奏/形式偏好投影，`no_memory` 仅保留当前控制。这些偏好不在 packet 预算体内，因而不能把本报告的预算比较当成整个规划输入或 API 成本比较。

### 4.3 旧评分问题与保守选择

来源链正确仍可能产生过时的教学安排。修复前，1,800 预算下 1,132 个引用评分的实际动作中有 192 个使用旧评分，而且动作类别与最新显式评分不同，分布为原题重做、未解决卡点和源撤回轨迹各 64 例。典型 BFS 案例 `clp-bffbec225444891af742` 只保留旧独立成功，较新的受助重做被预算排除。

修复将合法候选按真实时间/Event ID 排序，并只保留预算能容纳的连续前缀。用同一校正后的 v2 事后审计逐案例配对，结果为：

| full / 1,800 的 1,584 例 | 修复前 | 修复后 |
| --- | --- | --- |
| 引用了最新适用评分的实际动作 | 940 | 1003 |
| 引用了旧评分的实际动作 | 192 | 0 |
| 没有评分相关动作（NA） | 452 | 581 |

原来 192 个旧引用中，63 个改为采用最新评分，129 个停止使用旧结果；原来正确的 940 个保留。不能把停止判断的 129 个算作“教学判断正确”。在有实际评分的 1,311 例中，修复后 1,800 预算仍有 308 例没有评分相关动作；另有 273 例本来没有适用评分。

这 308 例包含全部 138 个最新评分失败案例，以及 170 个成功案例；它们都没有 episode 交付。138 个失败案例的两个合法过程候选均因预算遗漏。这不意味着所有相关 Fact 信息都没有交付，但说明小预算没有充分支持依赖过程包的错误诊断。

3,200 预算的 full 在两轮均为 1,311 个评分动作、0 个旧引用、273 个 NA，没有这项数量提升。修复后全部 12 组、两个预算的事后审计共 23,066 个适用条件通过，旧引用和非法交付来源均为 0，另 14,950 个条件是 NA。这些是来源/时序一致性，**不是教师评价或学习收益**，也不保证找到 24 个 anchor 候选池之外的最新历史。

此项是正式结果引出的**事后审计**，不是事先冻结的教学主指标。初版审计曾有交付绑定和 transient scope 缺口，校正后用同一旧轨迹重算仍复现 192 个旧引用；原工具与统计保留，正式评分和 gold 没有回改。

校正后的[修复前审计](../../evals/education_memory_v2/results/formal-02-freshness-v2/summary.json)、[修复后审计](../../evals/education_memory_v2/results/formal-03-freshness-v2/summary.json)和[逐案例配对汇总](../../evals/education_memory_v2/results/formal-03-freshness-v2/paired-before-after.json)均已归档。压缩文件保留原始字节与解压 SHA，NA 没有改计为通过。

## 5. 教师审核与尚未验证的价值

教师材料分为数据/标签有效性审核和真实计划盲评两个阶段。最终材料已从 `formal-03` 实际保存的计划重新导出，按方向与轨迹分层抽样；评分表保持空白，协调员映射不得提前交给审核者。导出覆盖 198 个案例、4,752 个实际方案条件，不将 4,752 当作独立学生数。导出材料不等于获得教师评价；[准备记录](../../evals/education_memory_v2/results/formal-03/teacher-review-preparation.json)保留来源与分发包 SHA，审核状态为 pending、已填评分为 0。

原导出的固定种子编号可以被推回实验组，已记录这个盲法缺口；新增[私密打包工具](../../scripts/package_private_teacher_review.py)使用独立随机编号并分离 `reviewer/` 与 `coordinator/`。只分发前者，私密映射留待评分锁定后解盲。内容本身仍可能使评审者猜测组别，不能承诺完全盲化。

下一阶段应由真实计算机专业教师先修订题目与证据标签，再独立评价约束是否适配、依据是否充分、下一步是否合理、是否区分受助与独立表现。真实学生研究需要独立任务、延迟保持与迁移测量。当前没有教师评分、真实学生样本、学习收益或线上回答质量结果。

仍有明确实现边界：时间延续仅支持可审计的带时区 ISO 截止时间；BM25 是词法通道，尚无向量语义检索；episode 只覆盖原生概念题/代码练习的正式评分，缺失 canonical 题目关系时保留 null；有界候选和图窗口仍可能遗漏长尾材料。

教育回放还有 69 个原题重做案例的辅助等级忠实度检查失败：驱动传入原请求等级，原生评分路径因同题已有作答而保守地记为受助，与轨迹原始标注不同；没有因此升级为独立迁移。这说明轨迹标注与原生评分语义不完全等价，仍需审核。该差异与题目原话未形成 Fact、小预算遗漏失败过程一起披露，不能用“没有错误升级”代替完整的证据忠实度结论。
