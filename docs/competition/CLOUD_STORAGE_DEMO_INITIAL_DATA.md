# 云存储技术 Demo：初始化数据与首次对话

本文档用于创建一个“做一个作品或实验”类型的 LearnFlow Demo。内容只覆盖注册、项目初始化、主题资料与第一次初始对话；不包含后续 Tutor 对话脚本。

## 1. Demo 目标

让学习者围绕对象存储分片上传，完成一个可运行的可靠上传原型，并留下可验证的异常恢复、状态机和幂等设计产物。

## 2. 注册数据

以下字段可直接用于 Demo 注册页：

| 字段 | 填写值 |
| --- | --- |
| 用户名 | `xiaoz` |
| 显示名称 | `张` |
| 学习阶段 | `工作中` |
| 每周学习小时 | `5` |
| 当前背景 | 有 Python 和基础网络知识，了解文件上传，但没有系统学习过对象存储的分片上传、断点续传和幂等恢复。 |
| 关注方向 | 对象存储、分片上传、断点续传、幂等设计 |
| 偏好的学习方式 | 讲解、示例、动手实验 |
| 职业目标 | 云计算后端开发 |
| 密码 | 在注册页面现场临时填写；不要写入文档、数据库脚本或截图。 |

如果 `xiaoz` 已存在，使用同样字段创建一个带后缀的 Demo 用户名，例如 `xiaoz_demo`。

## 3. 项目初始化数据

在“创建项目”页面选择项目类型：`做一个作品或实验`。

### 项目主题

```text
对象存储分片上传：断点续传与幂等恢复实验
```

### 学习目标

```text
理解对象存储中 Bucket、Object、Key、Upload ID、Part Number 和 ETag 的作用；掌握分片上传失败后的状态恢复、失败分片重试和完成请求幂等处理；能够独立设计并验证一个支持程序重启、网络中断和重复请求的可靠上传流程。
```

### 预期产物

```text
一个可运行的分片上传原型、一份异常恢复测试记录、一张上传状态机图，以及一份幂等与一致性设计说明。
```

## 4. 主题资料与官方 URL

### 本地主题资料

优先上传仓库中的补充资料：

`D:/jbgs/LearnFlow/docs/云存储技术-权威补充资料-2026-09-13.md`

资料覆盖对象存储基本概念、分片上传协议字段、断点续传、超时与重试、幂等、可验证示例和常见误区。

### 官方 URL

添加以下 AWS 官方文档作为项目来源：

<https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html>

这是 Amazon S3 Multipart Upload 概览，包含 Upload ID、Part Number、ETag、分片完成与失败清理等关键定义。

## 5. 来源录入与核验顺序

1. 创建项目并保存上面的三个项目字段。
2. 在主题资料/来源区域上传本地 Markdown 文件。
3. 添加 AWS 官方 URL，等待抓取完成。
4. 点击“重新核验”或同等的来源检查按钮。
5. 确认来源基线显示：`ready`、`覆盖 100%`、`缺口：无`。
6. 点击“作为项目基线”确认这两份资料用于项目生成。
7. 再进入讲义和练习生成；如果页面仍显示旧的“缺少主题资料”，先刷新项目列表或重新打开项目，让旧的 blocked 任务状态被新资料基线替换。

不要把密码、API Key、Token、Cookie 或 `.env` 内容放进本 Demo 文档或主题资料。

## 6. 第一次初始对话（仅此一条）

将下面整段作为项目创建后的第一条用户消息发送：

```text
我想完成这个云存储项目。请先不要直接给出完整实现方案，先通过几个问题判断我的基础，并根据我的回答安排第一步学习任务。

我目前知道文件可以上传到云端，但还不清楚对象存储和传统文件存储的区别，也不了解分片上传、断点续传、Upload ID、Part Number 和 ETag 分别有什么作用。

请先问我 3 个简短问题，重点判断：
1. 对象存储与传统文件存储的区别；
2. 分片失败后如何恢复；
3. 如何避免重复上传或重复完成请求造成错误结果。

暂时不要直接给答案。
```

发送后停止录入；本 Demo 不需要预先编写或导入第二轮及之后的对话。
