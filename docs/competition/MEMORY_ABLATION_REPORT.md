**结论：升级有效，但不能宣传整体准确率 100%。** 在六条合成轨迹、35 类场景和同一数据的版本对照中，2,800 预算下完整系统全证据齐备率从 59.26%（96/162）升至 85.19%（138/162）。仅事实组为 81.48%（132/162）。四类长尾问题全部漏召回；未覆盖问题仍有背景误召回；纯图依赖诊断也暴露一跳限制。

## 1. 研究问题与证据边界

本实验回答三个问题：完整 Fact–Module–Claim 结构在什么场景比仅原子事实有帮助；本次检索升级是否改善相关证据覆盖与上下文冗余；更长历史、弱查询与边界数据会暴露哪些失败。

测量对象是 `build_five_kernel_context()` 输出的 ContextPacket。查询直接进入真实共享检索实现，按 Web 与 Desktop 两种宿主装配运行。实验不生成 Tutor 回答，不使用在线 LLM，不测自然语言答案质量、学生掌握率或学习效率。数据是程序生成并直接建表的投影夹具；预制 Module/Claim 不能充当实际摘要模型质量的证据。真实事件、reducer、合成 worker 与撤回则由单独的工程合同测试验收，绝不混进检索准确率。

## 3. 条件与评分

| 条件 | 实际变化 | 解释边界 |
|---|---|---|
| `full` | 完整活动投影、核路由、缓存、关系读取 | 仍有候选数、节点数、一跳及预算上限 |
| `facts_only` | 删除 Module/Claim 与其关联边，重建 head | 保留核标签、scope、Fact 之间的边；不是普通无结构向量库 |
| `no_relations` | `max_paths=0` | 只关 MemoryEdge 路径，不关独立概念附件 |
| `no_kernel_routing` | 所有核均可深读 | 原隐私与 scope 过滤仍生效 |
| `no_head_cache` | 每轮刷新 head | 用来检查缓存一致性与开销 |
| `recent_facts` | 仅保留每学习者/项目最新 24 个活动事实 | 是有意受限的近期基线，不能代表所有短期记忆方案 |

“原文证据覆盖”指该题所需的固定原文片段实际出现在可归因的 items、heads 或关系端点中。隐藏 ID、provenance 引用、截断掉的尾部都不计命中；合法旧版本只进入历史集合。它是证据提取指标，**不是通用语义正确率**；同义改写即使合理，也不被本评分器认定为原文命中。独立概念附件参与禁止内容审计，不被悄悄算成具有原始 Fact 归因的 gold 命中。

全证据齐备率要求一个正例的全部 gold 同时出现。严格精确率以所有被识别原文单元为分母；不属于本题 gold 的背景也计为多余，因此低精确率不等于这些背景全是错误事实。

禁止内容哨兵扫描**完整 JSON packet**，涵盖概念附件、guidance、provenance；节点身份/scope/状态检查针对可归因可见片段，Fact evidence_grade 检查针对 items。审计只支持本夹具覆盖的断言，不是任意格式的隐私渗透测试，也不宣称对所有路径元数据都完成了独立语义校验。

## 5. 完整结构与仅事实的取舍

| 条件 | 原文证据平均覆盖 | 全证据齐备 | 严格 gold 精确率 | 平均 token 估算 | 中位 ms |
|---|---:|---:|---:|---:|---:|
| `full` | 85.19% | 85.19% | 23.46% | 2085.39 | 33.08 |
| `facts_only` | 84.72% | 81.48% | 27.09% | 2083.26 | 31.11 |
| `no_relations` | 81.48% | 77.78% | 23.08% | 2043.60 | 30.11 |
| `no_kernel_routing` | 77.78% | 77.78% | 22.79% | 2088.20 | 33.56 |
| `no_head_cache` | 85.19% | 85.19% | 23.46% | 2085.39 | 42.02 |
| `recent_facts` | 5.56% | 3.70% | 5.49% | 768.09 | 10.28 |

完整系统在八项恢复场景每条都找齐；2,800 档仅事实每条缺一项，造成 6 个正例不齐备。移除关系后，全证据齐备率为 77.78%，说明当前案例中的直接依赖仍有价值。关闭核路由同为 77.78%，说明把所有核都放进深读并非免费。

仅事实组仍有优势：严格精确率 27.09% 高于 full 的 23.46%，中位延迟较低；5,600 档两者覆盖与齐备相同，均为 85.19%，仅事实平均估算 2,543.60，完整系统 3,047.84。额外摘要并非每次都值得支付成本。本轮支持“按任务选择摘要与原文并保留例外”，不支持“完整结构在所有场景必胜”。

缓存重建与缓存读取的 630 个配对条件，所有非计时字段一致；2,800 档重建中位 42.02 ms，缓存读取 33.08 ms。它说明本夹具中缓存节省刷新开销，不能当作对所有线上状态更新的缓存正确性证明。

同为 full / 2,800，新增历史为 256、1,024、4,096 时中位延迟分别为 27.56、32.44、50.22 ms，p95 为 45.19、49.08、69.44 ms。每档只有两条合成轨迹，且主题不同，属于体量压力观察，不拟合复杂度或宣称容量上限。

## 7. 失败分析与独立机制诊断

正式 full 的四类失败在 1,800、2,800、5,600 都没有靠增加预算解决：

1. **别名/跨语言**：查询 `MVCC snapshot visibility`，库中为中文“多版本并发控制的快照可见性”。当前词项逻辑不能建立这组对应，6/6 漏召回。
2. **错拼**：`semaphroe fairnes` 对应 `semaphore fairness`，6/6 漏召回。
3. **长正文尾部**：gold 是超过 900 字填充后的唯一溢出检查结论。节点可以被选中，但展示截断使原文单元不可见，6/6 漏召回。这里失败是“未提供必要内容”，不能拿正确 ID 冒充成功。
4. **同词长历史**：大量近期 `测量历史` 与低显著度的旧待办竞争，旧必要事实在 256、1,024、4,096 的干扰层中均漏召回；稀有英文词项的旧事实则 6/6 命中。改进了稀有词检索，不等于解决所有长尾。

三类未覆盖查询中，只有零匹配词项组为空。含“学习/记录/证据”等泛词的两组仍返回背景，空证据率合计 6/18 = 33.33%。实验没有调用回答模型，因此只能称作背景误召回，不能直接称作已经生成幻觉。

正式“两跳需求”和“95 条边”均成功，但 packet 显示远端事实可以由查询关键词直接选中。因此，不能把这两个成功写成“已实现两跳图遍历”或“消除了边窗口限制”。

正式 Web 输出检查之后，另冻结[机制探针说明](../../scripts/evals/memory_retrieval/MECHANISM_PROBES.md)，共 12 条查询、72 次 Web 调用，**不并入正式指标**：

| 诊断 | 1,800 | 2,800 | 5,600 | 解释 |
|---|---|---|---|---|
| 两跳需求，只保留入口词项 | 覆盖 2/3；齐备 0/6 | 覆盖 2/3；齐备 0/6 | 覆盖 2/3；齐备 0/6 | 一跳返回邻居后，没有继续取到第二层 |
| 密集边，去掉“基准源”词项 | 覆盖 1/2；齐备 0/6 | 覆盖 1；齐备 6/6 | 覆盖 1；齐备 6/6 | 查询仍与目标共享“依赖”，并非严格的纯边窗口实验；只能证明小预算有缺口 |

这些探针是看结果后设计的诊断，不是预注册盲测。完整 packet 与正式结果一样保留。下一轮若要单独测 80 边窗口，应消除所有远端词项线索，并单独控制候选与节点预算；本报告不把尚未执行的试验写成结论。

## 9. 优化建议（尚未实现，不计入结果）

- **查询归一与混合候选**：先补可审计的术语别名、大小写/错拼规范化，再评估语义候选通道；统一 scope 过滤与重排。分别报告精确词、同义、错拼的增益及误召回，不能只看总均值。
- **原文分段与例外保留**：长 Fact 按语义单元提供带来源的片段，目标词窗口与限制条件共同入包；保留完整事实 ID 和正文 hash。摘要不得抹掉“仅单线程通过、并发未验证”等限定。
- **多样性与时序召回**：给同主题多时间段预留候选配额，区分“当前状态”与“最初未完成”，避免仅因热度/时效丢失旧问题。
- **受预算控制的图扩展**：对结构依赖做显式、有界的第二跳；排序同时考虑关系意义、节点相关性、历史状态，检测循环并过滤每一跳。先做纯边机制试验，不凭当前成功样例承诺突破 80 边窗口。
- **条件式摘要使用与未覆盖处理**：汇总任务保留模块优势，局部事实问题优先取原文；低相关背景减少或标记缺少直接证据。完整系统与 facts_only 应按场景比较成本，避免固定偏向任一层。

所有建议继续遵守 EvidenceEvent → reducer → KernelMutation → KernelState → Fact/Module/Claim 权威链。它们是下轮工作，不是本次部署的完成项。
