# 教育学习者画像与记忆消融实验

> 后续实现与同场景复验见 [教育记忆升级报告](EDUCATION_MEMORY_UPDATE_REPORT.md)。本报告作为升级前基线保留，数字与失败记录不改写。

> 本报告取代“用检索覆盖率评价整个教育画像系统”的解释方式。旧实验原始结果保留，仍可作为读取组件的回归证据。

本轮测试了从学生操作形成画像、向教学交付信息、由现有离线规划器采用信息的连续过程。**结果显示：画像和指导已经形成，并不保证规划器使用了它们。** 在 3,200 预算下，Web 与 Desktop 完整配置均交付了 88/104 项正向教学要求，但真实离线计划仅满足 8/24 项场景要求。facts_only 分别为 84/104 和 8/24。

这些数字是固定合成场景的契约检查结果，**不是学生画像准确率、回答正确率或学习收益**。本轮没有真实学生试验，没有在线 LLM，也没有修补被测产品来提高分数。

## 1. 本次实际测了什么

教育记忆应回答：学生在哪里、理解到哪里、需要什么支持、当前为什么学，以及能否独立完成。为此，本轮分开测量三个层次：

| 层次 | 实际执行 | 评分对象 |
|---|---|---|
| 画像形成与更新 | 教学输入 API 函数、原生 user_message、结构化资料/概念自述事件；真实判题、纠错、复习入口 | 五核实际存储、来源、帮助等级、偏好与目标更新、掌握边界 |
| 教学信息交付 | 同一写后快照调用真实 ContextPacket 与 scoped planner context | 当前指导、带来源的正文、到期与隔离排除 |
| 教育行为采用 | 现有 generate_learning_task_plan 的确定性离线分支 | 时间安排、优先处理知识缺口、渐进撤除提示、当前目标 |

身份和课程题库是人工创建的合成资产；学生输入和答案由固定脚本给出。概念题的对错、Attempt、纠错过程和复习证据由正式入口产生，脚本没有填写假 `correct=True` 事件或伪 Attempt ID。结构化资料与概念自述从已登记事件边界进入，未评估这些资料的自然语言抽取。

写入使用既有 `EvidenceEvent → reducer → KernelMutation → KernelState`；普通记忆继续形成 Fact，再由真实队列和 worker 形成 Module/Claim。即时 `teaching_directives/teaching_preferences` 按现有设计不进入 Fact 合成，它们由真实归约形成并直接投影为教学指导。将它们强行包装为 Fact 会改变实验对象。

API 函数直接接收隔离实验身份，未经过 HTTP 登录中间件。业务时钟被固定并推进；“4 天后复习”是模拟时间，不能称为真实持续学习 4 天。所有 SQLite 数据库均位于临时目录，网络连接被拒绝，真实 worker 使用 `deterministic` 模式。

## 2. 场景、规模与分母

固定四条主轨迹，分别使用数学分数比较、物理串联电路、编程递归终止、生物光合作用题面。每条有 41 个观测点、32 条无关课堂接触事件；另有其他课程、会话和外部学习者作隔离负例。相同机制换四种题面，不等于四次独立发现，也不能估计总体泛化能力。

| 场景组 | 主要观察 |
|---|---|
| 学习起点、困难与返回 | 自述“学过”仍待验证；原生对话缺口；当前卡点解除；单轮指导消费；先补基础再返回 |
| 教学支持的变化 | 10 分钟限制；长期先例后理；默认代码语言、本次覆盖、更新、取消、迟到旧事件 |
| 暂时状态与隔离 | 明确负荷、跨会话、8 小时后；第三方引用；跨课程与跨学习者 |
| 自然表达探针 | “只剩10分钟”“今天只有1小时”“我今天很累，请放慢节奏” |
| 长期背景与纠正 | 目标探索/确认；同概念自述；真实合成前后；Claim 纠正、撤回；干扰后恢复较旧背景 |
| 学习与纠错 | 真实错答、换讲法、受助原题重做、变式验证；缺失、跳过、不会分开 |
| 稳定性与重复 | 重复请求幂等；同题面不同 ID；一次独立复习；模拟跨 72 小时的独立复习与审核变式 |

每个宿主有 164 个观测点。每点运行 7 个配置、2 个预算、2 次重复，共 **4,592 次读取与离线规划调用，双端合计 9,184 次**。重复只检查确定性，不增加样本量。Web 和 Desktop 结果单独保留；2,296 组对应条件的交付/规划判定与教育语义 hash 均一致。

每宿主形成层有 300 项检查；每个预算/配置有 104 项正向交付、40 项排除检查、24 项规划采用检查。形成层不随读取开关变化，因此不重复计入七个配置。零 Fact 的来源链审计记为不适用，不用空集合给形成能力加分。

主学习者在最后一个已评分时间点合计产生 288 个 Event、372 个 Mutation、572 个 Fact、32 个 Attempt，已观察到 20 个 Module 和 20 个 Claim（包含历史版本）。这是四名主学习者的计数，不含隔离负例学生；最终观测后执行的 worker 排队处理不混入此计数。

## 3. 消融如何定义

| 配置 | 干预 |
|---|---|
| full | 原有完整读取与真实规划 |
| facts_only | 在独立读副本删除 Module/Claim 节点及关联边；保留实际五核状态与即时指导 |
| recent_facts | 同上，仅保留每学习者最近 24 个 Fact |
| no_relations | `relation_paths` 输出预算为 0；其他读取和个人概念图保留 |
| no_guidance | 从返回包去掉 `teaching_guidance`，保留另一个 adaptation 通道 |
| no_head_cache | 每次真实重建 head；与 full 比较教育语义 |
| no_memory | 原有离线规划器接收空画像上下文，交付为空；不改变判分或权威状态 |

事实副本的删除仅用于读取消融，不写回原始实验库，更不影响日常数据库。facts_only 同时去掉 Claim 作为纠正锚点的作用，因此 full 与它的差异不能全部归因于摘要质量。no_relations 只消融返回路径，不是禁用所有图索引与排序；本轮没有单独的教育依赖图 gold，持平不能证明关系层无用。

## 4. 实测结果

### 4.1 画像形成与更新

Web 与 Desktop 各自的 300 项检查均通过 284 项。每端 16 项未通过分为：

- 三种自然表达探针在四种课程中未产生绑定本次输入的目标指导，共 12 项。
- 相同题面使用不同题目 ID 仍触发 checkpoint stable，共 4 项。

其余已测形成检查通过，包括明确偏好更新/取消、来源绑定、受助等级、原题重做与一次变式不直接写稳定掌握、复习稳定门、目标确认和真实合成。该通过数按断言计数，包含同一轨迹多个时间点，不能写成“画像准确率 94.67%”。

### 4.2 正向信息交付与真实计划采用

以下计数在 Web 与 Desktop 分别运行后完全相同，分母按单端列出；40 项排除检查各配置均通过，单独列出以避免无记忆配置靠负例取得高分。

| 配置 | 1,800：正向交付 /104 | 1,800：计划采用 /24 | 3,200：正向交付 /104 | 3,200：计划采用 /24 |
|---|---:|---:|---:|---:|
| full | 72 | 4 | 88 | 8 |
| facts_only | 72 | 4 | 84 | 8 |
| recent_facts | 68 | 4 | 80 | 12 |
| no_relations | 72 | 4 | 88 | 8 |
| no_guidance | 12 | 4 | 24 | 8 |
| no_head_cache | 72 | 4 | 88 | 8 |
| no_memory | 0 | 0 | 0 | 0 |

直接移除指导通道会降低以指导为对象的交付指标，这是可预期的通道消融结果；它本身不是教学改善的因果证据。更有价值的观察是：移除指导后规划采用计数没有改变，说明本轮真实离线规划器并未有效消费这些指导。

full 相对 facts_only 的四项增量来自纠正内容：完整配置保留了 Claim 目标，纠正 Fact 能获得现有锚点排序支持；删除 Claim 后相应正文没有进入有限包。它不是本轮证明了“长期摘要推理更强”。较旧背景在 recent_facts 中丢失，说明仅保留最近事实会损失部分教育历史。

### 4.3 成本与确定性

3,200 预算的样本中位耗时如下，包含 scoped planner context 和真实离线计划生成，不包含建库、造历史、合成或独立审计。两端平均字符数四舍五入后相同。

| 配置 | Web 中位耗时 ms | Desktop 中位耗时 ms | 完整返回包平均字符数 |
|---|---:|---:|---:|
| full | 20.03 | 21.78 | 8,848 |
| facts_only | 33.90 | 32.34 | 8,822 |
| recent_facts | 26.78 | 27.85 | 7,785 |
| no_relations | 16.54 | 17.85 | 8,837 |
| no_guidance | 22.02 | 22.82 | 7,727 |
| no_head_cache | 28.12 | 27.67 | 8,848 |
| no_memory | 5.61 | 6.24 | 73 |

配置顺序在每个观测点固定随机打乱，两个宿主顺序运行。该数据来自本机环境，不能证明部署延迟或成本比例；缓存、数据库大小和调度仍会影响计时。字符数不是模型 token，未调用模型所以没有实际模型费用测量。`no_guidance` 的 manifest 仍保留删除指导前的原始预算估算。

两端均未观察到预算检查失败、两次重复的教育语义差异或 full 与 no_head_cache 的教育语义差异。逐节点、完整包哨兵、指导来源/期限和正文片段审计未发现本轮定义的违规。每端 164 个快照中，16 个尚无 Fact 的来源链检查为不适用，88 个有 Fact 无 Module，60 个同时检查了 Fact 来源链和 Module 闭包；有数据的检查均通过。审计范围不等于完整隐私或安全认证。

## 5. 失败样例与原因

**时间要求送达，但未改变计划。** “今天只有10分钟”产生正确且有来源的指导；真实计划仍按调用方的 45 分钟默认值输出。现有离线规划只读取少数字段，没有解析 `teaching_guidance.time_budget`。明确高负荷的支持指导也未转化为预设的缩短计划要求。

**本次偏好可能在预算裁剪中丢失。** 本次 JavaScript 示例要求已正确存入状态；同一回合存在时间、卡点、返回、篇幅等要求时，即时指导子预算裁掉了代码语言项。3,200 总预算下该子预算仍上限为 800 个现有估算单位。必须区分“没有形成偏好”和“形成后未交付”。

**受助成功已送达，但缺少渐进撤提示安排。** full/facts_only 的 planner context 有 `supported_success` 指导，却没有标量 `practice.assistance_level`。现有 fallback 只读取后者。recent_facts 偶然取到了较早换讲法事件的 `guided` Fact，从而命中撤提示分支；最新评分 Fact 的 subject 与规划请求固定的 checkpoint subject 不同，有限预算内的竞争影响了选择。这里不能将 recent_facts 概括为更好的教育记忆方案。各配置仍有通用独立验证阶段，失败的是针对受助经历的渐进撤提示安排。

**自然表达只在本轮所测入口上失败。** 三个探针使用 `vnext_teaching_input_received` 原文入口。不要将结果外推为所有原生聊天入口都无法理解这些句子；不同入口当前有不同归约分支。评分要求指导绑定本次 Event，旧的同值、已过期记录不能代替新请求。

**题目 ID 去重不足以证明稳定掌握。** 普通概念评分把同 checkpoint 内至少两个正确且独立的不同 item_id 作为稳定门代理。相同题面换 ID 也满足该门，未检查内容、题族、间隔或之前是否看过相同答案。这是对现有代理规则的教育鲁棒性探针，而非声称当前代码没有执行它自己声明的规则。

稳定结论的 `evidence_ids` 另外包含了之前的错答和受助记录，因为来源列表直接取最近事件。它们没有参与“正确且独立”的数量门槛，但混入支持列表降低了归因精度。此处是 `checkpoint:*` mastery；独立的 `review:concept:*` 路径仍在本轮通过了 72 小时与审核变式的检查，不能混称为绕过复习稳定门。

## 6. 实验完整性与限制

- formal 使用固定源码工作树 `cb0b3d0304fcdfcbf0cff183c3d2769196fa1dec`，被测共享核心 0.2.3 / relevance-budget.v2。实验脚本、协议及全部被测 Python 源码另存 hash 和内容，结束时再次校验。Web 182 个、Desktop 189 个归档源码文件逐一核验一致，运行期间无源码变化或联网尝试。报告提交所在分支后续同步的其他改动不算入被测基线。
- 保留五次 pilot。第一次发现虚拟时钟替换破坏 datetime 类型检查；第二次审计器误用了不存在的 expires_at 字段；随后校准了来源/状态/正文判据、陈旧同值指导假阳性，以及同一 Attempt 的正式重做事件被过窄来源 gold 拒绝的问题。它们不计入正式成绩。
- 未修改被测产品以修补失败，未删除失败场景，未把旧检索结果换名冒充教育实验。
- Module/Claim 由真实确定性 worker 产生，未测试在线摘要质量；profile 展示输出已留存，但不是每个展示字段都有独立 gold。
- 未调用在线 Tutor/规划模型，不能据此判断在线模型遵从指导、讲解质量或实际学习效果；未运行浏览器教学体验和真实学生试验。
- 所有正式场景都是开发场景，来源语法与部分实现已在设计时阅读过，不能称为盲测。

## 7. 下一步教育优化的优先级（未实现）

1. 让真实教学/规划消费者使用已经送达的结构化时间、当前困难与受助反馈；先避免“记住了但没采用”。
2. 统一关键教学输入在不同入口的语义，增加自然表述与澄清策略；未识别时保留未知。
3. 在指导预算内保留本次明确覆盖要求，并解释被省略的要求。
4. 区分题目身份与独立教育证据；核查重复内容、题族与答案暴露，筛出稳定结论真正的支持事件。
5. 为规划任务提供与 item 级 Practice 证据一致的检索坐标，再比较长期归纳、关系和事实通道的场景收益。

这些是根据失败提出的后续工作，不是本轮完成项。继续遵守既有事件归约和确定性判定权威。
