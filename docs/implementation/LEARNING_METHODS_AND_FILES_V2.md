# 学习方法与文件闭环 v2

2026-09-07。本次同时适用于 Web 与 Desktop，不部署、不迁移日常数据。

## 保留的入口

| 方法 | 保留理由 | 对话责任 | 文件与验证 | 维护验收 |
| --- | --- | --- | --- | --- |
| 清晰讲解 `guided_explanation` | 陌生主题的默认起点；与一次性简单讲解区分，带领学习有可恢复任务 | 核心模型、最小例子、一次表达；按需要使用局部追问或示例 | 不强制生成文件；需要证据时进入正式验证 | 未知、只确认、求助不算答题；到预算给退出入口 |
| 费曼复述 `feynman_dialogue` | 已接触内容后复述查漏，现有单缺口诊断可维护 | 陌生主题先示范；只修一个候选缺口；最多两轮修订 | 引用当前材料，复述不计掌握，验证另走正式提交 | 不让表面关键词替代正确性，不无限要求重讲 |
| 讲义与练习共学 `learning_file_study` | 长内容、可留存阅读与正式作答需要独立文件流程 | 短导入、具体阅读位置、回答卡点、结果复盘 | 配对讲义与练习；文件生成、已读和真实提交驱动状态 | 无文件不能声称已选；无本轮 Attempt 不能声称已练 |

苏格拉底追问和示例渐隐不再作为新任务的主菜单入口；在清晰讲解中保留为局部教学手段。两个稳定 ID、状态定义和旧运行仍可读取、恢复和显式使用，兼容 API 不删除。注册表 `entry_policy=primary/legacy` 是菜单投影的唯一来源；自动推荐只选三个维护入口，不再悄悄开启旧方法。

不合并简单讲解和清晰讲解：前者回答一个问题后回到自由态，后者是学习者选择的带领学习流程。没有增加主 Agent、框架或第二套长期学习状态。

## 已确认的根因

- 原文件生成实际调用短微学习卡，完整讲义只有一个 section；模型候选题还会被固定“来源支持／学习常识”题覆盖。
- 原 materialize 把全局任务改成隐藏项目的 checkpoint scope，但原 Session 仍为 global；下一轮因此 ownership/scope 失败。
- 学习文件选择、阅读和练习只根据聊天文字推进；真实文件操作未回到 SkillRun，任意一句话可能误推进，“好的”则一直不推进。
- 确认卡生成后未改成打开入口；练习阶段仍优先打开讲义；答错的“再想一想”按钮被禁用。
- 练习请求总是传 none/original，明确受助与刷新后的原题重做也可能被误记为独立首次作答。

## 新文件合同

`learning-file-package.v2` 复用 `Lecture / ConceptQuestion / Exercise`，`.lflecture/.lfexercise` 仍是数据库对象的逻辑入口。

- `POST /api/learning-files/tasks/{id}/generate` 接受可选 `file_kinds`，默认讲义和练习。只补缺失对象，已有发布版本、草稿、批注和尝试不覆盖。
- 生成不再隐式启动 MicroLearningRun。任务与 Session 原有 scope 保留；内部生成范围放入 `execution_state.artifact_scope`，所有读取再次验证 ownership。
- 讲义支持目标、机制、具体例子、边界等多个章节，以及稳定阅读锚点、来源引用、版本和配对练习引用。完整讲义候选由 Learning Design 生成，失败不把主题占位话当正式内容。
- 练习保留通过现有题型、答案确定性、重复等静态检查的学科候选。固定泛化常识题不能替代学科验证；质量声明保持未校准，不声称静态门证明内容真值。
- 回包兼容 LearningTask，新增 `file_generation`，区分 ready、partial、blocked 并给出 gaps。成功部分保持可打开，不把部分失败显示为整套已完成。
- 文件引用按 task.artifact_refs 选取，不以同关卡全部文件猜测配对，尤其不依赖全局任务的空 checkpoint_id。

## 对话与纸张交接

既有 SkillRun actions 增量支持 `sync_artifacts`，只读服务端文件、带版本的已读事件和当前运行的正式 Attempt，复用零 target 运行事件同步：

```text
真实讲义可读 → reading_with_anchor
本轮明确已读 → practicing_in_file
本轮对应练习已有正式 Attempt → verification_ready
```

聊天的“生成好了／读完了／答完了”不替代这些事实。文件聊天不消耗一般追问预算。生成、标已读、提交后 UI 刷新同一 Session/SkillRun；已生成确认卡变成打开讲义和练习，主按钮随阶段变化。讲义记录按学习者、文件与版本隔离的阅读位置；正文保留在纸张。

练习结果保留历史 Attempt 摘要和可操作纠错入口；重复请求复用同一幂等 ID。辅助等级由真实提示和明确反馈保守记录。服务端把同题再次提交钳制为 retry；已返回标准答案的概念题再次提交至少为 guided，不能被旧客户端重报 original/variant/独立成功。正式变式和间隔复习继续使用已有专用流程。

连续求助达到支援预算时，用户可以改为清晰讲解或暂停回自由对话。直接解释请求仍可以回应，不再被同一固定退出文案挡住。切换方法的幂等键包含当前运行版本，反复切换不会重放第一次切换的旧结果。

## Contract impact

Registry `2026-09-07.4`（Desktop同后缀）、Skill runtime v7。稳定 Skill/Tool/Capability/Event ID 保持；新增选择策略元数据、sync_artifacts 动作、文件生成与历史投影字段，不新增表，不改变三类 Agent 或五核 reducer。

旧全局运行只有在 learner/session/run、旧 MicroLearningRun 反向引用和内部 task_artifact scope 全部匹配时，才惰性恢复原 scope 并保留 artifact_scope；真实项目冲突继续拒绝。此兼容代码不代表本次操作过日常数据库。

只修提示词无法解决 scope、幂等、文件版本和阶段一致性，因此这些不变量落在服务端与类型化交接；模型只负责内容候选和当前步骤的措辞。

## 验收方式

回归覆盖两端 runtime、生成 API、文件播放器交接、旧运行兼容、重复提交、辅助等级、注册表漂移及构建。全链路使用隔离数据库与确定性样本，在线学科内容质量仍需独立抽检，测试通过不代表学习效果或模型题目质量已经校准。具体执行结果见本次任务最终报告。

## 浏览器验收补齐的交接

- “开始独立验证”原本只创建后台 MicroLearningRun、把浏览器任务暂停，没有可作答的客户端。现在当前对话内打开验证面板，复用已登记的复述、练习与纠错接口，正式 run ID 随绑定持久保存，刷新后仍可继续；换浏览器或本地任务缓存缺失时也从服务端恢复绑定，客户端暂停/完成旧事件不得覆盖服务端状态。
- 练习的“进入纠错”原本只打开普通复习页。现在题目内加载它自己的 RemediationCase，按服务端允许动作换讲法、看步骤、看示例、原题重做与变式验证。没有纠错案例的已通过题不显示虚构卡点。
- 变式提交增量接受 client_submission_id；服务端在状态门禁前校验 learner/case/item/内容并安全重放，已经完成的成功响应也可恢复，不重复写 Attempt/事件。无 key 客户端保持兼容。解释动作与答案判定仍由既有确定性服务控制。
- 新验证面板和纠错面板作为既有对话、练习工作台的内部组件登记，不增加特殊文件类型，不建立平行掌握状态。
- 从文件进入独立验证时，排除当前文件的题干、变式以及已展开的纠错变式；生成与重新生成都保留排除约束。程序链接使用另外的情境题。无法获得足够新题时返回明确的 409 提示，事务保存点保留原任务、文件与进度，不能通过换题目 ID 把原题伪装成独立验证。规范题干去重只能阻断文本重复，学科语义等价与迁移难度仍需要内容抽检。

## 维护与后续质量抽检

新方法入口必须同时具备：明确的开始条件、有限步骤和求助预算、一个可用退出入口、恢复后的状态一致性、正式验证交接。通过这些检查后再考虑新增主方法；不以提示词名字增加菜单项。

新学科内容抽检应分别检查讲义事实、题目答案与变式是否测量相同目标；静态结构验证不代替学科审校。本次离线程序链接样本包含不同情境的正式变式；旧系统缺失变式合同而采用原题重排的历史题仍需单独治理，不能据此评价迁移能力。
