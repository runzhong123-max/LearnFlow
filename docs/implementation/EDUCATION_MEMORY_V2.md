# 面向计算机专业群学习者的记忆与规划升级

Contract impact：共享核心 `0.2.5`，Web registry `2026-09-08.9`，Desktop registry `2026-09-08.9-desktop`；控制 `teaching-guidance.v2`、解析 `teaching-control-parser.v2`、检索 `relevance-budget.v3`、规划 `learning-plan-guidance.v2`。这些是现有能力的策略升级，未增加第四类 Agent、并列画像权威或新模型写工具。EvidenceEvent v1、ContextPacket v2、LearningTask plan v1 和数据库表保持兼容。旧事件不自动回放，旧状态不被本次发布批量改写。

## 为什么升级

上一轮计算机专业群合成轨迹回放暴露了三个不同断点：学生即时预算常未被解析；明确跨日安排仍按原有会话 8 小时过期；读到的零散 Fact 不足以证明某次练习的帮助程度与来源关系。此前统一汇总分数不能解释这些断点，通用对话检索分数也不能代替教学价值。

本次将目标限定为：让明确控制准确进入五核链，令真实评分过程能在预算内被读取，并让计划明确显示采用了哪些证据。实际掌握、教学策略、评分和通过条件仍由原有确定性规则决定。

## 输入与时效

`teaching_control_parser.py` 是有界纯函数，保留原输入中的字符范围。引号和代码内容被遮蔽，第三方陈述、假设与不确定表达按局部语段处理；有效的本人请求可以和这些语段并存。解析器返回候选控制及不包含原话的拒绝原因，不直接写状态。`reduce_teaching_guidance` 仍由统一 reducer 调用，所有变更经过 EvidenceEvent → KernelMutation → KernelState。

默认临时文本控制限于当前会话，8 小时到期；turn 控制可能在下一次输入时提前失效，持久偏好不受此期限限制。时间预算、当前优先事项和返回安排，只有明确且带时区的 ISO 截止时间才可以延伸到同一项目、同一关卡的后续会话，最远不超过来源事件后 168 小时。缺失时区、过去时间、含糊期限、冲突期限或超过上限的安排保留不确定诊断，不悄悄退回默认 8 小时。`source_scope` 是原始来源，`application_scope` 是应用范围，旧字段 `scope` 兼容指向应用范围；来源不能被改成读取会话。v1 条目保留原有期限和 scope 解释，未知版本拒绝读取。

当前优先事项与返回位置属于临时教学控制，修改或取消不等于删除长期 Value Claim；长期目标确认仍使用原有显式事件流程。按事件时间与来源顺序处理覆盖和取消，重复事件不能重复激活，旧事件不能覆盖更新状态。明确“取消这个项目的临时时间预算安排”等有限表达仅撤销同项目、同关卡的已有同类窗口；墓碑保留 `cancelled_window_source_event_id` 和原到期时间，使用 `inherited_cancelled_window` 期限依据，不新开窗口。普通取消只作用于本会话，不能扩大到其它项目。诊断只说明解析/过滤原因，不能作为学习证据或新的掌握结论。

## 检索与学习过程

原有精确词、可审计别名、错拼规范化、时序候选、限定条件片段和有界图路径继续使用相同 scope 与归档过滤。本次增加在同一受限候选池上的 BM25 词法评分；这不是向量语义检索。图路径仍显式有界、逐跳过滤和循环检查，本次没有宣称突破原来边窗口的所有长尾问题。

新增 `learning_episodes` 是按需构建的只读包，不新增表，也不将邻近 ID 或同主题事实拼成一次学习经历。首版仅支持原生概念题与代码练习的正式评分事件，要求：

- Fact、已应用的 Mutation、Event 在 learner、核与来源 scope 上一致；节点通过现有可见性、归档、答案与 Human 限制。
- Event 的明确 attempt_id 对应真实、已评分的 LearningAttempt；题目、关卡、路线和未删除项目的 ownership 一致。
- 结果与 Attempt 一致，帮助等级有合法来源；缺失帮助或独立性保留 null，不能凭默认值推断独立成功。

包包含真实评分时间、Attempt/Fact/Mutation/Event ID、实际题目角色、结果、帮助等级、来源片段的 hash 与范围，以及遗漏/未知限制。canonical_item_id 在没有真实关系时为 null。首版不把相似题目或相邻会话冒充审核变式，不复制原始提交、标准答案或评分解释。

ContextPolicy 独立开关为 `enable_episodes`、`enable_bm25`、`enable_aliases`、`enable_fuzzy`、`enable_temporal`、`enable_summary_boost`；图机制沿用 max_paths/max_hops。默认最多 3 个过程包，每包 6 个事实。`retrieval_diagnostics` 报告候选、实际命中/采用、过滤及截断；启用开关不等于发生贡献。

预算仍使用现有字符估算口径（JSON 字符数 / 3.2 向上取整），并将新增过程、诊断、组件策略一并计入。它不是模型 tokenizer 的精确 token 或实际 API 费用。来源不足和预算截断必须保留，不能凭摘要补造事实。

首次完整矩阵暴露了预算保留旧独立成功而丢掉新受助重做的问题，修复后合法过程候选按真实评分时间、Event ID 从新到旧排列，预算只保留连续前缀；新包放不下时不以较短旧包代替。规划端同时间也按 Event ID 选取，历史反馈使用“记录显示”措辞。这仅保证已进入有界候选池的过程顺序，不保证找到池外的全部最新历史；缺少过程时不能宣称已有当前反馈。

## 对计划的实际影响

Web 与 Desktop 的 `_scoped_planner_context` 消费同一个共享读取包。共享规划编译器按 `(occurred_at, Event ID)` 择取最新有效反馈；只有完整排序键相同时才保留原生指导，时间相同但 Event 更新的过程投影仍可覆盖旧指导。旧练习不能覆盖已交付的新反馈。已有时间预算、支持请求、卡点及优先目标仍受确定性约束；新增返回位置用于核对暂停位置。

| 真实证据状态 | 教学准备 | 不能推断 |
|---|---|---|
| 明确评错 | 定位第一个错误，再进入现有纠错闭环 | 人格、情绪或固定能力 |
| 受助答对或原题重试 | 渐进撤提示，再安排无提示小变式 | 独立迁移成功 |
| 答对但帮助未知 | 确认辅助程度，再安排独立小检查 | 无提示成功 |
| 明确独立成功 | 独立变式或理由检查 | 稳定掌握 |
| 结果不完整 | 区分不会、跳过和缺失提交 | 已答错 |

最终计划增加 `teaching_decisions`：动作、策略版本、实际来源 Event ID、尚未知的信息及 `mastery_inference=false`。这是可检查的规则执行说明，不是隐藏思维链，也不成为画像证据。模型输出经同一确定性约束；重规划保留已完成阶段与原验收条件，当前准备只能进入仍可执行的阶段。

## 验证与发布边界

新增边界回归、双端共享契约检查及两个规划消费者验证。新版实验位于 `evals/education_memory_v2/`，旧数据、旧 gold 和旧报告继续保留；结果必须与运行 SHA、策略、预算、变体及实际组件使用情况一起解读。所有数值以已生成的运行记录为准，不预填提升比例。

教师审核表保持未填写状态。合成轨迹、来源检索、确定性计划采用率和真实学生学习收益是四种不同证据；本次实现与离线验证不能替代教师审核或学生实验。显式 ISO 期限是首版可审计边界，尚不能宣称覆盖“这周五之前”等全部自然时间表达；向量检索、开放式语义判分、完整跨题 canonical 关系和真实课堂效益仍待后续验证。
