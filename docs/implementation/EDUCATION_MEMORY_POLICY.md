# 教育记忆证据与规划消费升级

> 本文记录 0.2.4 的首次证据门与规划修复。当前 0.2.5 对解析、控制期限、读取过程和计划依据的增量变更见 [EDUCATION_MEMORY_V2.md](EDUCATION_MEMORY_V2.md)；下文“本轮未调整”指首次修复，不能用作当前版本状态。

Contract impact：registry `2026-09-08.8`，共享核心 `0.2.4`；新增确定性策略 `concept-evidence.v2` 与 `learning-plan-guidance.v1`。三类 Agent、五核、事件稳定 ID、EvidenceEvent v1 和 LearningTask plan v1 保持兼容，无数据库迁移。只读规划策略不形成学习证据。

## 修复的证据缺口

教育消融发现普通概念题会因两个不同 item_id 独立答对而写入 checkpoint stable；重复题面换 ID 也能通过该门，且支持列表混入错误和受助记录。

本轮取消普通概念评分的稳定升级。每次作答保留正式结果、来源和策略版本，分别为 `verified_once`、`correct_with_support`、`correct_assistance_unknown` 或 `needs_review`。服务端在事件中补充 resolved `attempt_role` 和 `assessment_policy_version`，不采信客户端伪造的角色和版本。一次或多次普通题答对都不能替代长期稳定证据。

长期稳定继续复用既有 `review-policy-v1`：末次失败后的独立合格复习、至少 72 小时跨度和审核变式。原有显式 transfer 路径保持独立，不把它误当作旧普通题结果。这里的审核变式是现有格式与元数据门，不能宣称已验证所有题目的教育新颖性，也不能证明学生在系统外没见过答案。

旧事件、Fact、Module、Claim 和日常数据库不回填、不删除。新的普通评分不再制造该类稳定结论；已存在的旧 checkpoint stable 仍可能被展示，需要单独审计与经事件链的纠正。本轮不声称修复了历史画像。对原事件重新归约会使用当前保守规则，必须作为显式重建操作，不在升级时自动运行。

## 规划消费者

Web 与 Desktop 共用 `learnflow_core.planning_guidance`。输入是 `_scoped_planner_context` 已按当前 learner/project/checkpoint/session、归档、期限与生命周期过滤的教学指导，输出是只读的确定性计划约束。编译器进一步拒绝到期、未来、取消、未知版本与无来源条目。它不从模型文本推断控制，不新增画像状态，也不重新引入原始 Human 敏感信息。

| 有效指导 | 对最终计划的约束 |
|---|---|
| 时间预算 | 不超过当前分钟上限；明确本次只推进一个小目标，未完成阶段留待后续 |
| 明确支持请求 | 分小步推进，当前安排至多 20 分钟；不推断情绪、医学状态或长期能力 |
| 当前困难 | 优先拆解当前卡点并做小检查；只从与当前指导同一 Event 的已选 Fact 保留具体卡点与来源，避免用通用指令覆盖细节或复活旧卡点 |
| 自述已解决 | 停止重复旧卡点；用小检查衔接，不升级掌握 |
| 受助成功 | 渐进撤提示，再做无提示小变式 |
| 最新独立成功 | 转入独立变式/理由检查，旧 guided Fact 不替代当前状态 |
| 帮助未知/缺失作答 | 先确认帮助等级或缺失原因，不伪装为独立成功或答错 |
| 当前优先事项 | 采用当前明确目标，历史目标仅作背景 |

最终 plan 附加 `teaching_constraints`（策略、实际来源、scope、到期时间）和适用时的 `session_focus`。1–4 分钟用于一个微步骤，不能被模型校验的默认 5 分钟下限重新扩大，也不表示整个任务能在该时间内完成。原 API 的预计任务时长输入范围保持兼容，用户表达的即时预算由正式指导进入。

约束应用在旧 Fact 重建之后，同时覆盖直接 fallback、无模型 generate、模型 JSON 校验、重规划和已有候选 plan_override。约束保留已确认候选的阶段 ID、方法、验收条件及来源；按当前证据调整教学目的，模型省略受助后的练习时补回该阶段。任务完成与判分继续使用原来的确定性运行时。重规划保留完整已完成阶段，新的准备要求转给当前首个未完成阶段，随后仍独立验证。计划保留裁剪前的 planning_basis_minutes；新预算或原预算到期后从原任务估计重算，避免临时 10 分钟永久压低后续安排。用户显式编辑任务预计时长时同步该基数；模型阶段按 learn、practice、verify、consolidate 的顺序规范化，防止先验证后补卡点。

`support_need` 不再从 learner 级短期状态无范围搬入新任务；当前支持由已过滤的指导提供。长期明确偏好的旧兼容读取保持不变。指导缺失时保留原有 scoped Fact 和默认规划行为，不把“不知道”补成用户事实。

## 验收与限制

先保留原教育消融脚本、gold 和数据规模，运行升级版本，与 `410e94e` 报告中的冻结产品基线比较。另加独立开发的反例回归：重复题 ID、不同题同会话、受助与帮助未知、短时预算、来源/到期/取消、当前指导覆盖旧事实、故意违约的模型输出、重规划/候选入口。新增用例不冒称教师编写或真实学生盲测。

本轮未调整自然表达解析、指导子预算、图扩展与语义检索，也没有线上模型效果或真实学习收益试验。原消融中的相应失败应继续保留。执行结果及完整原始记录在新版教育消融报告中单独列出；不预填通过数量。
