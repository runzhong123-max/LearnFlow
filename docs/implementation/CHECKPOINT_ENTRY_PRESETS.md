# 三类项目的关卡进入预设

2026-09-14。关卡仍以正式 Checkpoint、LearningTask 和 Session 为权威，对话串行推进。`learnflow.checkpoint-entry.v1` 是讲义、习题与待完成文件的内容设计，不是新的教学状态机。

- 学习型：路线提案按知识先备递进，每关配置 `knowledge`、讲义重点和一份习题集目标。已有学习路线自动得到这对入口，后续解锁读取正式关卡完成状态。
- 实验型：项目准备工具要求具体串行路线，按最终交付的接口或组件拆为实现关卡；每个 `implementation` 指定原子文件路径及职责。环境准备、部署和复核可以单列。新提案必须经过原有确认才物化，不能把占位文件计划说成代码已生成。
- 实践型：第一关以综述进入，提供总纲讲义与小练习入口，整体工作流程只使用公开的阶段标题；后续关卡对应工作步骤。固定维护案例保留原 key、版本、材料、hash 与判定规则，新增进入展示不改写已发布案例。自定义正式路线可携带 overview/workflow 设计。

`entry_preset` 为正式路线提案的兼容可选字段，储存在 Checkpoint.brief。实验项目候选的 `checkpoints` 为可选串行规划，纳入原候选 hash 与确认事务。新版 Tutor 准备实验项目必须提供该规划；旧 API 客户端和已确认的通用路线仍可恢复，不自动重排已有项目。旧实现关卡没有明确文件时，显示“和导师明确本关文件”，不编造语言或路径。

进入桌面关卡后，对话上方的一条入口显示讲义、习题、待完成文件与桌宠。点击生成沿既有受管文件 API，生成结果留在本关对话；已有文件可直接打开。生成器读取本关预设，固定案例只提供当前开放的材料。缺资料、内容质量检查失败或部分生成失败要如实返回，不能用空白题假装准备完成。文件与习题并不在进入页面时暗中生成。

“准备文件”先读真实路径，存在则保留；不存在时经用户点击创建空文件，再读取并作为工具结果加入当前对话。目录关联、路径保护、冲突检查与操作事件全部复用桌面文件服务。新确认的文件计划在操作交付时逐项核对文件版本引用或同关卡设备报告清单；不以文件齐备判定代码正确或掌握。点击文件卡进入代码纸，四档帮助仅在纸内选择；关卡概览只展示师生分工。真实工程助手仍沿原来的确认运行、确认写回规则。

实验和实践的桌宠入口明确绑定本关正式 Session；桌宠显示当前关卡和“请导师看下一步”。操作中通过现有快捷键选中文字，核对引用后在同一关卡请教；此版本不是持续屏幕监控。云端保留现有截图上传限制、文字引用与本地身份边界，不新增后台采集、自动提交或第四类 Agent。

Contract impact：两端 registry 升至 `2026-09-14.3` / `2026-09-14.3-desktop`，登记 `checkpoint_entry_v1`，复用路线、项目工作流、文件生成、文件服务、帮助与桌宠能力。仅添加内容设计数据；旧 API 载荷可用，不迁移数据库，不改变 EvidenceEvent、五核、判题或独立验证语义。关卡 Tutor 上下文过滤其他关卡的预设；锁定的实验/实践关卡不能生成材料。已开始关卡的预设与原有目标一起受不可变检查约束。

验证使用两端隔离测试数据库与模拟浏览器接口。覆盖三类默认进入、显式实验规划确认与重放、路径拒绝、已开始预设冻结、未来材料隔离、讲义生成目标、四档帮助显示位置与桌宠会话接续。在线模型、真实桌宠系统快捷键与真实桌面窗口权限需要在原生宿主验收，本轮不安装替换应用或发布。
