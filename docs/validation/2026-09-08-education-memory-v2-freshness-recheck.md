# 评分时序修复的复验约定

本约定在修复后运行开始前写下。`formal-02` 的教育全量事后审计发现小预算保留旧独立成功、遗漏新受助重做的问题；这些案例已被开发者看过。本次是已知缺陷的回归与相同固定样本复验，不能称为新的盲测或独立验证集。

## 固定改动

只调整合法 episode 候选内部的真实评分时间/Event ID 顺序、预算前缀保留和规划端同时间的 Event ID 顺序，并将历史反馈措辞改为“记录显示”。来源链、scope、评分、题目、gold、候选池上限和原有消融评分不变。

如果最新包不能在预算内交付，就不再用较短的旧包替代。保留缺少评分动作的案例数，不能靠全部不采取动作而宣称教学决策已改善。该规则仅覆盖已进入有界候选池的合法过程，不能推断已找到整个历史里的最新证据。

## 冻结矩阵与判读

- 新输出目录为 `evals/education_memory_v2/runs/formal-03`，不覆盖旧运行。
- 原教育 1,584 例，原 12 组，预算 1,800 / 3,200，仍为 38,016 条件。
- 原 LoCoMo 1,986 题，原 7 组与两个预算，仍为 27,804 条件。中性对话没有合法学习 episode；重跑检查这项修复是否产生意外变化。
- 采用 4 个教育分片、4 个 LoCoMo 分片，各案例仍只形成一次。并行度改变，因此不比较两轮单次延迟来证明性能改善。
- 产品、评测代码和数据均在开始时记录逐文件 SHA；源码漂移、漏条件与执行错误必须显式失败。原始失败、旧结果与可重建旧源码的差分一起保留。
- 同时报告两个预算下的当前/历史控制、原文/题目探针、过程交付、决策来源、预算和组件干预，不隐藏修复后的负收益。

新增 freshness 审计属于从 `formal-02` 引出的事后诊断。使用真实保存的 Event/Attempt/Fact 记录，限定同 learner/project/checkpoint 与当前输入时间，按评分发生时间/Event ID 对照实际计划。分别报告适用条件、缺少动作、引用旧评分、动作与最新显式结果不一致以及 NA；不改原冻结评分，不用模型补教学标签。

教师材料从 `formal-03` 的实际方案重新导出，分层方式不变，再经过私密随机重编号打包。旧材料保留并标明修复前；所有评分仍为空白/pending。
