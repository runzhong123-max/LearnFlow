# Role Atlas 对话冷启动与学习路径挂载验收

## 实现范围

- 新建岗位进入固定展示台的右侧对话。支持“我还不明确”、联网岗位建议、公开 Hub 固定版本预览与拉取。
- 岗位说明覆盖任务、能力与工作场景；改进文字与附件可反复补充。只有确认当前修订才允许生成图谱，后台使用保存的最新说明与资料。
- 有附加资料仍执行独立检索；冷启动与迭代发现可修复的证据、知识技能、任务或培养关系缺口后进行有预算的补研。
- 每次岗位版本提交同时写入学习路径挂载任务。通过同一中央账号验证和真实源图提交，复用或创建节点；以正式回执显示结果。定义或证据不足时至多启动一轮原身份自动补研，再挂载新版本。
- 自动队列在限量读取之前筛选可补研记录；失败任务只允许从明确记录且精确匹配的已提交部分版本接续，原失败状态保留。
- 管理员可按“岗位澄清 / 说明”查看和导出修订输入、来源、模型调用、确认、失败与构建关联；兼容尚无新表的历史数据库。

- 浏览器边界验证：新项目不会复用旧草稿；清空浏览器草稿仍可恢复服务端资料；创建、改稿、确认期间离开页面均不会被迟到响应重新导航或触发下一步构建。
- 真实 SQLite / ZIP 回归覆盖来源原件继承、账号隔离、并发确认、失效确认、重复投递、部分结果接续、凭据脱敏与导出校验清单。

早期 sandbox 下 `tsx` IPC / 本地 HTTP 监听被拒，已在允许本机测试监听的执行环境重跑并通过。供应商与生产切换属于后续独立验收，不把受控模型测试当作真实供应商或岗位内容权威性的证明。

真实供应商预检发现，模型能完成检索与回答，但可能越过岗位说明的数组数量或长度等结构约束。现将完整 JSON Schema 随上下文发送；格式不合格时在原总时间预算内自动纠正一次，复用已取得的资料，不重复检索、不放宽证据与内容校验。持续无效输出、供应商错误与用户取消不会形成可确认的空说明。新增回归覆盖格式纠正、无重复检索、总预算、供应商错误及取消边界。

## 契约与边界

Contract impact：新增兼容 `role-intake/v1` 操作产物及 `role-learning-auto/v1` 中央源图挂载协议；学习路径源图 v2 增加可选独立根节点提案，旧调用仍可使用原手工 resolve/commit。注册表 2026-09-09.1 保留教育记忆声明。

挂载写的是课程来源结构，重要行为留操作审计，学习掌握目标为零；不增加第四类主 Agent，不绕过 EvidenceEvent/reducer 写五核，不把生成说明或图谱视为掌握证据。不自动改写既有岗位历史；中央身份撤销、项目/会话版本改变及真正不可用的供应商仍是停止条件。

生产上线结果、最终提交、镜像、备份和真实供应商冒烟必须追加实际执行记录后才能宣称部署完成。
