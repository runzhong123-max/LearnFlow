# 学习型任务转化功能 → 个性化自适应学习对接说明

版本：`1.0`  
知识点级交接协议：`learning-task-knowledge-to-personalized-learning-v1`  
纠偏回传协议：`personalized-learning-to-task-conversion-feedback-v1`

## 1. 对接目标

学习型任务页面中的每个知识点都可以直接进入个性化自适应学习。交接时不是把整份任务无差别复制给下游，而是围绕用户点击的知识点，确定性裁剪出：

- 企业任务与学习型任务简介；
- 当前唯一知识点及其学习资源；
- 真正使用该知识点的任务步骤；
- 与这些步骤强相关的技能点；
- 步骤—知识点—技能点特殊关系；
- 下游允许生成和不得改写的字段；
- 理解偏差或弱关系的回传地址。

个性化自适应学习负责“怎么学”，包括学习目标、讲解内容、学习顺序、练习、评价和学习者适配；不得改写企业任务名称、实际任务步骤、阶段产物、检查点或已锁定的强关系。

## 3. 推荐调用流程

```text
用户点击学习型任务中的某个知识点
  → POST 知识点级交接接口
  → 学习型任务转化功能校验任务、知识点和步骤关系
  → 返回 learning-task-knowledge-to-personalized-learning-v1
  → 个性化自适应学习根据 generation_contract 生成内容
  → 如发现关系不密切或范围理解错误，POST 纠偏反馈
  → 学习型任务转化功能形成可追溯复核请求
```

推荐使用 `POST` 进入接口，因为它在返回交接数据的同时会记录一次明确的跨功能导航事件：

```text
POST /api/learning-task-conversion/tasks/{task_card_id}/knowledge/{knowledge_id}/personalized-learning-entry
```

只读预取时可使用：

```text
GET /api/learning-task-conversion/tasks/{task_card_id}/knowledge/{knowledge_id}/personalized-learning-entry
```

两者返回相同版本的数据结构。接口复用当前 LearnFlow 登录态。

## 4. 前端调用示例

```ts
export async function openPersonalizedLearning(
  taskCardId: string,
  knowledgeId: string,
) {
  const response = await fetch(
    `/api/learning-task-conversion/tasks/${encodeURIComponent(taskCardId)}`
      + `/knowledge/${encodeURIComponent(knowledgeId)}/personalized-learning-entry`,
    {
      method: 'POST',
      credentials: 'include',
      headers: { 'Content-Type': 'application/json' },
    },
  )

  if (!response.ok) throw new Error(await response.text())
  const entry = await response.json()

  // 推荐将entry放入路由状态、Store或服务端会话，不要塞入URL。
  sessionStorage.setItem(
    `personalized-learning:${entry.entry_id}`,
    JSON.stringify(entry),
  )

  return entry
}
```

## 7. 下游必须遵守的生成边界

`generation_contract.immutable_fields` 中的字段禁止改写。下游可以生成：

- `learning_objectives`：围绕当前知识点的个性化学习目标；
- `learning_content`：讲解、示例和资源编排；
- `learning_sequence`：依据学习者状态调整的学习顺序；
- `practice_activities`：练习、仿真或实操活动；
- `assessment_plan`：评价方式与达成判断；
- `learner_adaptations`：难度、节奏和支架调整。

下游生成的每项内容应保留以下追溯字段：

```json
{
  "source_entry_id": "ple_...",
  "source_task_card_id": "ltc_...",
  "source_knowledge_id": "kp_...",
  "source_step_ids": ["step_..."],
  "source_relation_ids": ["rel_..."]
}
```

## 8. 纠偏回传接口

如果个性化自适应学习认为某个知识点范围、技能范围或步骤关系不正确，调用交接包 `feedback_contract.url`：

```text
POST /api/learning-task-conversion/downstream-feedback
Content-Type: application/json
```

空模板：

```json
{
  "schema_version": "personalized-learning-to-task-conversion-feedback-v1",
  "task_card_id": "",
  "correlation_id": "",
  "source_system": "个性化自适应学习功能",
  "status": "accepted_with_feedback",
  "issues": [
    {
      "issue_id": "",
      "feedback_code": "step_mapping_mismatch",
      "severity": "warning",
      "relation_id": "",
      "step_id": "",
      "knowledge_id": "",
      "skill_id": "",
      "message": "",
      "suggested_correction": ""
    }
  ],
  "summary": ""
}
```

实例：

```json
{
  "schema_version": "personalized-learning-to-task-conversion-feedback-v1",
  "task_card_id": "ltc_network_vlan_001",
  "correlation_id": "personalized-review-20260817-001",
  "source_system": "个性化自适应学习功能",
  "status": "accepted_with_feedback",
  "issues": [
    {
      "issue_id": "issue_vlan_001",
      "feedback_code": "step_mapping_mismatch",
      "severity": "warning",
      "relation_id": "rel_vlan_config_001",
      "step_id": "step_configure_ports",
      "knowledge_id": "kp_vlan_8021q",
      "skill_id": "sp_vlan_config",
      "message": "该关系能够支撑端口配置，但当前学习内容还需要区分 Access 与 Trunk 两种操作边界。",
      "suggested_correction": "保留原关系，在知识点范围中补充两种端口模式的适用条件和验收差异。"
    }
  ],
  "summary": "任务事实可用，建议补充端口模式的适用边界。"
}
```

`feedback_code` 允许：

- `weak_relation`
- `incorrect_knowledge_scope`
- `incorrect_skill_scope`
- `step_mapping_mismatch`
- `missing_prerequisite`
- `unsupported_task_fact`
- `other`

状态规则：

- `accepted`：不得携带问题；
- `accepted_with_feedback`：必须至少携带一个问题；
- `rejected`：必须至少携带一个问题，并说明拒绝原因。

同一 `task_card_id + correlation_id` 重复提交会更新同一条反馈记录。反馈只进入复核流程，不会直接覆盖企业任务事实；修订后的任务必须重新经过内容与关系门禁。

## 9. 错误处理

| HTTP 状态 | 原因 | 下游处理方式 |
|---:|---|---|
| `401` | 未携带 LearnFlow 登录态 | 使用同源请求并携带 Cookie |
| `404` | 任务或知识点不存在 | 返回任务页并刷新任务包 |
| `422` | 知识点无步骤映射、反馈结构错误 | 阻止生成并展示明确错误 |
| `502`/`504` | 任务服务暂时不可用或超时 | 保留 `entry_id`，允许用户重试 |

不得在接口失败时使用模型猜测任务步骤、知识点或关系作为替代数据。

## 10. 联调验收清单

- [ ] 从任务页面点击任意知识点能调用 `POST personalized-learning-entry`。
- [ ] 返回的 `knowledge_id` 与用户点击项完全一致。
- [ ] `source_steps` 至少有一步，并且每步都真实引用该知识点。
- [ ] `strongly_related_skills` 只包含来源步骤引用的技能点。
- [ ] 下游保留 `entry_id`、任务 ID、知识点 ID、步骤 ID 和关系 ID。
- [ ] 下游不改写 `generation_contract.immutable_fields`。
- [ ] 下游发现偏差时能够成功提交纠偏反馈。
- [ ] 用户不需要下载或重新上传 JSON 文件。
