# 教师与技术审查指南

本指南是评审材料，不应进入被测系统上下文。所有现有教学标签均为待审核建议。

## 按什么单位审核

先审72个任务族，再审每族22条历史分支。先确认216道题的技术含义和可判性；不要因为脚本给出正确计算结果就默认教学路线合适。每族的三道题必须提供足够材料，且迁移变化应涉及边界、结构、约束或情境，不以换变量名作为充分理由。

从 `catalog/*.json` 或审核队列取一个实际 family_id，可生成完整中文评审材料（包括具体题、答案、时间线、允许方案和禁止行为）：

```bash
python3 evals/computing_learner_profile/dataset.py review --family-id <family_id> --output /tmp/family-review.md
```

也可用 `--case-id <case_id>` 只审一个情境。`inspect` 仅显示被测系统可见材料；`review` 包含评审端答案，二者不要混用。

## 每条轨迹审核五件事

1. 当前请求和可见历史是否足以支持标签？引用的观察是否属于本人、授权项目且查询前可见？
2. 该学生的困难、支持需求和目标是否有明确证据？是否把评分错误、未提交、跳过、不会、受助完成混为一谈？
3. 允许哪些不同但合理的下一步？证据不足时的澄清、低负担诊断和保守验证能否通过？
4. 禁止行为是否会造成实际教学后果，而不是仅与作者措辞不同？不能按出现“撤除提示”等关键词评分。
5. 去掉或替换关键历史后，哪些判断应改变、哪些仍可保持？不要求两个有效教学方案必须不同，也不要求系统重复陈述所有历史。

## 重点反例

- **相同产物，不同帮助**：示例后完成和独立完成应保留证据强度区别，但都可能合理地进入新的独立诊断。
- **过期与取消**：旧时间限制不能变成永久限制。允许系统询问当前可用时间。
- **旧错与新证据**：后来正确不能抹去历史，也不保证能排除旧错误规则；既允许继续诊断，也不能忽略新表现把旧错永久化。
- **未知与理由**：辅助未知不得自动归为独立或抄袭。错误一般规则可能恰好算对当前题，不能强称当前逻辑矛盾；可以触发诊断，不能机械判成“全会”或“全不会”。
- **小组与个人**：小组产物通过不证明每位成员能独立做；个体诊断应与贡献未知匹配。
- **环境与学习**：题目未执行是环境问题；不能制造学生错误分数。
- **自然表达**：当次要求写在当前请求里，应对每个未来基线可见，不能靠隐藏当前指令制造记忆优势。

## 审核记录

复制 `data/teacher_review_queue.csv`，填写 reviewer、decision、notes，保留不同评审者的独立版本。decision 建议为 `accept`、`revise`、`reject`、`out_of_curriculum`，不能覆盖原始待审文件来伪装原始生成即通过。

先独立审核共同样本并报告一致与分歧，再讨论修订规则。记录哪个标签依据课程材料、哪个是可接受教学方案判断、哪个需要补充证据。合议产生新版本时保留旧版本和差异，不根据系统已输出的答案追改 gold。

## 对后续实验的限制

这批数据可验证“在给定历史下教学决策是否有依据”。固定历史回放不会告诉我们另一种教法会让学生下一次怎样作答；不能据此声称学习收益。没有教师审核时只能报告作者规则下的合成场景表现，不能写成教师共识或画像准确率。

跨学习者、未来记录等数据用于隔离测试，当前导出器已排除。以后要评估产品检索过滤，应由隔离测试环境装载这些外部记录，再通过真实的身份和范围接口读取；不能仅凭导出器过滤通过宣称生产系统过滤通过。
