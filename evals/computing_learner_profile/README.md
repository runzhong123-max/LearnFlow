# 计算机专业群学习者画像测试集

本目录先交付测试数据，不运行消融，不报告 LearnFlow 分数。它用于检查学习经历如何支持下一步教学、练习与能力验证，服务计算机专业群的学习者画像与规划评估。

可先浏览[全部72个任务族](CATALOG.md)，再查看[实际验证记录](VALIDATION.md)和[教师审核指南](REVIEW_GUIDE.md)。

**数据是原创合成案例，不是真实学生记录。教学标签由 AI 辅助编写，尚未由教师独立审核。** 技术题的可计算答案由独立校验脚本复算；这不等于教学方案已被证明最优，也不等于产品已经通过这些题。

## 数据规模与统计单位

- 9 个方向：程序设计、数据结构与算法、数据库、Web 后端、Web 前端、软件测试、计算机网络、Linux 与系统运维、数据分析与人工智能基础。
- 每方向 8 个任务族，共 72 个不同的专业任务族。
- 每任务族 3 道具体题，共 216 道题：基础题、近迁移题、延迟验证候选题。题目名称不代表迁移难度已经实证校准。
- 每族 22 类学习经历，共 1,584 条合成轨迹，每条在一个时间截面提出一次教学决策请求。
- 每族 12 组配对关系，共 864 组对比；同一轨迹会参与多个配对，不能把它们当独立样本。

1,584 不是学生人数，216 不是互相独立的任务家族，重复导出、重复调用、换预算或换模型均不增加独立样本量。22 类经历是跨领域复用的控制模板；规模主要来自 72 个领域任务与这些情境的组合，不宣称每条轨迹都由独立教师设计。范围充分性仍需本校课程和教师审核，不能只用数量证明代表性。

各类经历按相同数量构造，是用于检查机制的覆盖矩阵，不代表真实课堂中的发生比例。长历史中64条浏览记录是干扰，不能再计成64条独立教育任务。审计报告给出输入字符长度，字符数不是模型 token 或费用。

## 可直接使用的文件

| 文件 | 用途 | 能否给被测系统 |
| --- | --- | --- |
| `catalog/*.json` | 任务、三道题、正确/错误回答、计算输入与解释 | **不能整份提供**，包含答案 |
| `data/cases.jsonl` | 当前请求与时间线，包含故意放入的外部范围/未来记录 | **不能原样提供** |
| `data/rubrics.jsonl` | 可接受行为、必须保留的证据边界、禁止行为、来源引用 | 只供评审端 |
| `data/pairs.jsonl` | 配对关系、该改变或保持的语义 | 只供评审端 |
| `data/splits.jsonl` | 按任务族分组的开发、验证、留出划分 | 只供调度端 |
| `data/teacher_review_queue.csv` | 全量待审清单，审核人和结论留空 | 只供教师/审查者 |
| `data/manifest.json` | 数据文件 SHA-256、种子和真实性声明 | 只供调度/审计端 |
| `dataset.py export` 的输出 | 当前任务和截至查询时可见的本人同项目经历 | 可供未来被测消费者 |
| `checks/*_check.py` | 复算领域题答案，不运行产品 | 只供审计端 |

导出器为所有条件提供相同的基础参考题材料，以使当前课程任务自足；另外提供已在历史中展示过的题面和学生回答，排除题库正确答案、未来变式、判分标准、错误假设、推荐教学活动与情境标签。参考题的展示不证明学习者已学会。历史中已发生的学生正确回答属于合法历史证据，不属于未见题答案泄漏。

学习者原话导出时移除作者填写的 `topic`、已解析时间限制、有效期、偏好与目标更新标签，仅保留原文；不能把作者注释当成系统已经正确提取的画像。历史评测中的 outcome/assistance 是明确标为合成的观察反馈，未来评估正式形成链时仍需从原始提交独立判题，不能直接相信它们。

题目ID在导出时转换成不透明的稳定标识：同一原题重做仍能识别为相同题目，但不会通过 `near_transfer` / `delayed_transfer` 后缀提前告诉系统作者定义的迁移角色。

## 复现与检查

使用 Python 3.11+ 标准库，不连接服务、模型或生产数据库；实际测试版本记录在 `validation.json`：

```bash
python3 evals/computing_learner_profile/dataset.py build
python3 evals/computing_learner_profile/dataset.py validate
python3 -m unittest discover -s evals/computing_learner_profile -p 'test_*.py' -v
python3 evals/computing_learner_profile/audit.py
python3 evals/computing_learner_profile/dataset.py export --split development --output /tmp/computing-profile-development.jsonl
```

导出文件必须位于本目录外，并拒绝覆盖已有文件。未来执行模型评估时，只挂载该导出文件；不得把包含 `catalog`、`rubrics`、校验器和源代码的整个仓库交给被测 Agent。单条检查使用 `inspect --case-id <case_id>`。

`build` 是从目录中的版本化作者资料生成数据，不调用 LLM。相同源码和目录资料应逐字节复现相同数据。不要手改生成文件；修改作者资料或轨迹构造后重新构建、检查，并记录版本变化。

## 学习经历覆盖

| 组 | 情境 | 判断目标 |
| --- | --- | --- |
| 证据质量 | 完整示例后成功、一次独立成功、辅助未知、结果正确但理由依据不足 | 不把通过结果直接等同独立理解 |
| 验证与迁移 | 同一原题重做、新情境一次独立作答 | 区分熟悉、一次迁移表现与长期稳定 |
| 变化与纠正 | 未解决错误、后续一次独立成功、代同学录入后撤回 | 不固化旧错误，不用新题成功或撤回直接证明旧问题已解决 |
| 学习支持 | 临时时间限制有效/到期、明确反馈原讲法无效、本次覆盖长期偏好 | 当前有效要求优先，不推断固定学习风格 |
| 路线与目标 | 原目标、新确认目标替代、64条浏览干扰后的旧项目恢复 | 有依据地调整优先级、找回返回位置 |
| 证据缺口 | 缺失提交、主动跳过、明确不会、自述、小组产物 | 保留区别，承认个人证据不足 |
| 运维边界 | 评测环境缺失依赖、学生代码未执行 | 不把基础设施失败计为知识错误 |
| 对照扰动 | 无关偏好、其他学习者、其他项目、未来发生、过去发生但未来补录 | 不让不适用的信息改变当前判断 |

同一任务族的配对共享当前请求、身份和基础历史。身份是相互排斥的替代世界，未来回放必须逐案例重置环境，不能把两条分支写进同一学生的连续历史。有效期使用明确 UTC 时刻；发生时间和录入时间分别检查。

不同有效教学方案可能重叠：受助成功和一次独立成功都可以安排新的诊断，但对证据强度、提示安排和重复讲解的解释应恰当。**不得为了让完整画像取胜而要求每对输出不同，或把合理的澄清判错。** `current_input_override` 专门保留无需历史即可遵守的当前指令对照。

“旧错后出现新成功”配对同时增加支持反馈自述与一次新题表现，是经历组合对比，不能当成某一个组件的单因素消融；新题也不保证能排除旧错误规则。跨范围与未来记录在当前导出中被过滤，因此与基线相同的输入只检查导出边界，不计作下游模型抵抗这些干扰的独立成功。

## 划分、审核和后续使用

每方向按固定种子的任务族哈希分成 5/1/2 族，合计开发 45、验证 9、留出 18 族，对应 990/198/396 条轨迹。一个任务族的所有题、历史分支与对照都在同一集合。该划分不是按学生真实分布抽样，也不是概念完全不重叠的跨课程泛化测试。

**留出资料公开且作者已见，不是双盲、秘密题库或从未被模型见过的测试。** 后续开发只用开发集；根据验证集选择方案后冻结，再跑留出集。若根据留出失败修改实现，则该批转为开发/回归资料，下一次独立结论需新增并经教师封存的任务族。

教师审核需完成：本校专业/学段适配、题面充分性、错误回答合理性、迁移是否只换名字、多个可接受教学方案、相互矛盾的标签、评审者一致性。建议两位教师先独立评阅共同样本、记录分歧再修订规范；之后覆盖全量。审核结论保存在复制出的清单中，不伪填审核人或通过状态。若提供真实去标识案例，另建来源与授权记录，不冒充本批合成数据。

## 当前实现边界

Contract impact：无。这里的 observation 是**测试数据格式**，不是新注册的 EvidenceEvent，也不是另一套长期画像。没有变更生产 schema、Agent、评分规则、reducer 或版本，不写 KernelState/Fact/Module/Claim。

未来若评估完整画像形成，必须做明确的适配：从学生原始提交经过正式判题与 `EvidenceEvent -> reducer -> KernelMutation -> KernelState -> Fact/Module/Claim`，不能把本数据的 `outcome` 或 rubric 直接写成产品成功事件。不存在正式入口的行为应报告适配缺口。当前这一步只完成数据构建与数据检查，没有完成产品回放、浏览器教学闭环、模型判分、消融或真实学习收益试验。

技术题的可执行校验、轨迹完整性检查和教师教学审核是三种不同证据。实际覆盖与未验证项见 `VALIDATION.md`；课程依据见 `SOURCES.md`；逐项评审方法见 `REVIEW_GUIDE.md`。
